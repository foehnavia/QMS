  утверждён и проверен на машине (см. строки выше, `docs/architecture.md`). Следующее —
  INFRA-013 (операционная модель Cowork↔Claude Code), затем QMS-010 (разработка).
- **Q-07** — `מנה` vs глоссарий: пользователь трактует `מנה` = `פק"ע` (WO); глоссарий
  `_system/terminology` определяет `מנה` как «отмеренное количество, не весь WO». Модель
  следует пользователю; правка глоссария — по команде «обнови систему».
- **Item↔CG «многие-ко-многим»** — не материализовано на S1 (сейчас 0..1 через
  `characteristic→mapping→g_position→cg`). Материализовать (15-я таблица + правка §5) при
  появлении **CG второго уровня** (QMS-011, ревью S1).
- **Инвариант «находка ∈ деталь отклонения»** — в SQLite схемой не выражен; enforced
  **доменной проверкой в S2** (критерий приёмки S2). Композитный FK/дублирование `item_id`
  отвергнуты (денормализация + правка §5). (QMS-011, ревью S1).
- **Чертежи в БД — порог роста.** Скан 3–4 МБ × ~25 групп ⇒ файл БД под 100 МБ; это в
  пределах нормы для копирования, но полная выгрузка тянет блобы. Если файл перевалит за
  **~200 МБ** — вынести чертежи в отдельную таблицу с ленивой загрузкой. Флаг на **S7**
  (упаковка/бэкап). (QMS-013, ревью S3.)
- **Замена чертежа не переносит баллоны.** Координаты сохраняются намеренно, но при другом
  кадрировании скана баллоны переставляются вручную — совместить два скана нечем. Известное
  поведение, не дефект. (QMS-013.)
- **Диалог привязки пишет по действию, не по «Сохранить».** Кнопка подтверждает полноту и
  закрывает окно (подписи — «Готово» / «Закрыть»). Транзакция на весь сеанс привязки
  отвергнута: цена — потеря уже введённого при случайном закрытии. (QMS-013, ревью S3.)
- **Флаги на ETL-наряд S6:** (а) если реальная запись без направления вовсе — `finding.direction`
  сделать nullable (миграция); (б) если нужно отличать сентинел `quantity=9999` (выборка) от
  реального числа — добавить флаг. (QMS-011, ревью S1).
