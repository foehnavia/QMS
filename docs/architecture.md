# MIS-QMS — Архитектура и технологический стек

> **Статус:** утверждено дизайн-сессией QMS-009 (concept, 2026-08-10) и проверено
> эмпирически на целевой машине (5 фаз, все зелёные — см. §9). Основание —
> финализированный концепт `docs/model/` rev 1.00. Ратификация — `docs/decisions.md`.
> Канон модели (что за система) — `docs/model/_overview.md`; здесь — **как строим**.

## 1. Рамки

| Параметр | Значение |
|---|---|
| Развёртывание | одна машина (Windows), **офлайн** |
| Пользователи | один |
| Данные | автономны; в git/волт не кладётся **целый реальный документ/протокол** (с привязкой к компании), отдельные значения (деталь/WO/заключение) не sensitive |
| Источник импорта | ивритский Excel в Teams (разово/по одному Deviation), не Access |
| Роль приложения | **система-регистратор** (read+write), а не read-only вьюер |
| Горизонт стека | без переделки до этапа 1.5 (глубокий поиск) и «дальше» (генерация Word) |

## 2. Ключевые уточнения против ранней проработки ТЗ

1. **Access/ODBC исключён.** Источник — Excel (`openpyxl`), без `pyodbc`/ACE и ловушки
   разрядности 32/64. Airtable-прототип снят по безопасности → автономная локальная БД.
2. **Приложение — источник истины, не вьюер.** Этап 1 = рабочая база с ручным вводом и
   модерацией; Excel — разовый источник импорта.
3. **Схема нормализована глубже 3 таблиц.** Отдельные `Finding` и `Characteristic`
   `(item, local#)`, плюс канон-слой `CharacteristicGroup`/g-позиция + `Mapping` — он и
   даёт поиск прецедентов **между деталями** (сердце инструмента).

## 3. Технологический стек (утверждён QMS-009, проверен на машине)

| Слой | Технология | Обоснование |
|---|---|---|
| Хранилище | **SQLite** (stdlib `sqlite3`) | 1 пользователь/машина/офлайн; малые объёмы; встроено; бэкап = копия файла |
| Доступ к данным | **SQLAlchemy 2.x** + **Alembic** | ORM + честный SQL под джойны прецедентов и конструктор запросов; миграции; переезд на Postgres/MS SQL сменой строки подключения |
| ETL | **openpyxl** + stdlib **`re`** | чтение иврит/RTL Excel; детерминированный regex-парсинг, **без LLM в рантайме**; модерация оператором |
| Домен | чистый Python поверх SQLAlchemy | автообзор прецедентов, поиск L1/L2, глубокий конструктор запросов, карта полей документа |
| UI | **PySide6 (Qt)** | нативный RTL/bidi (иврит из коробки); stateful-формы; табличные виджеты; без веб-сервера; упаковка в `.exe` |
| Документы | **docxtpl** → **PDF через Word/Office** | Word-шаблон DS-QC.2-2 с плейсхолдерами и циклом по отклонениям; PDF конвертацией установленного Office (docx2pdf/COM) |
| Упаковка | **venv + PyInstaller** (onefile `.exe`) | один файл; офлайн-установка из `.whl` при закрытом pip |

> Отвергнуто: **Streamlit** (localhost) для entry-части — модель перерисовки, RTL-костыли,
> веб-сервер; оставлен как запасной для read-части. Прямой рендер PDF (reportlab/fpdf2) —
> двойная вёрстка при готовом Word-шаблоне.

## 4. Архитектура — слоями

Ядро (0–3, 5) **UI-независимо**; UI — единственный сменный слой.

```
[Excel иврит]                      [Word-шаблон DS-QC.2-2]
     | openpyxl + regex (модерация)         ^ docxtpl -> PDF (Word/Office COM)
     v                                       |
+---------------------------------------------------------+
|  Слой 3 — Домен: прецеденты · поиск L1/L2 · deep-query   |
|  Слой 1 — SQLAlchemy ORM (+ Alembic)                    |
|  Слой 0 — SQLite  app.sqlite  (источник истины)         |
+---------------------------------------------------------+
     ^ вложения = ссылки на файлы в сетевой папке (не блобы)
[Слой 4 — UI: PySide6]  формы ввода · карточка · конструктор запросов
```

## 5. Физическая схема (rev 0.1)

Суррогатный целочисленный PK для связей **плюс** генерируемый человекочитаемый
бизнес-номер (`DEV-YYMMDD-NNNN`, `INSP-YYMMDD-NNN`).

| Таблица | Ключ / связи | Заметка |
|---|---|---|
| `item` | PK `item_id`; `item_number` UNIQUE; FK type/connection/size | центр модели |
| `characteristic` | PK; FK `item`; `local_number`; UNIQUE(item, local_number); nullable self-FK `state_depending` | размер; спящий state-слой |
| `characteristic_group` | PK `cg_id`; `name` | ~20–30 групп |
| `g_position` | PK; FK `cg`; `g_index`; `nominal`; `tol_plus`; `tol_minus` | номинал/допуск зашиты |
| `mapping` | FK `characteristic` → FK `g_position` (0..1); код 99 = «позиции нет» | до регистрации (R2) |
| `deviation` | PK; `dev_number` UNIQUE; FK `item`; `wo`; `machine?`; `quantity`; `date`; `ncr?`; `decision_date`; `decision_dev`(4); `explanation`; `attachment` | целостность здесь |
| `finding` | PK; FK `deviation`; FK `characteristic`; `direction±`; `value?`; `dimension_point?`; `comment`; FK `zone?`; FK `deviation_type?` | решения не несёт |
| `inspection` | PK; `insp_number` UNIQUE; FK `deviation`+`finding`; FK `type`; `decision_insp`(bin); `protocol` | «наука» в протоколе |
| Справочники | `ref_item_type`, `ref_connection_type`, `ref_size`, `ref_zone`, `ref_deviation_type`, `ref_inspection_type` | контролируемые словари |

**Карточка отклонения — не таблица, а запрос-представление:** по `(item, local#)`, для
маппленых — по `(cg, g_index)`; единица вывода — **отклонение целиком**.

## 6. Нагрузочные сценарии → как ложатся на стек

- **ETL с модерацией:** openpyxl → regex `(размер, направление, величина)` → форма PySide6
  → правка оператором → commit (строка Excel = Deviation + массив findings).
- **Автообзор прецедентов (главный deliverable):** SQL-join по `(item, local#)` или
  `(cg, g_index)` → прошлые Deviation с `decision_dev`/`explanation`.
- **Поиск по уровням:** L1 точный · L2 (zone+type) · глубокий конструктор (все поля,
  AND/OR, диапазоны, вложенность, read-only) → динамическая сборка на SQLAlchemy. Этап 1.5.
- **`אישור חריגה`:** один на WO, цикл по отклонениям; поля из карточки (copy-from-card) в
  docxtpl-шаблон → docx → PDF (Word COM). Шаблон RTL, `bidi`/right-align на ивритских абзацах.
