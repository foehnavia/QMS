## 1. Что не так — факты, снятые чтением файла

Задача называет адрес `mapping_dialog.py:114`. **Адрес устарел**: строка 114 сегодня —
`setWindowFlag(WindowMaximizeButtonHint)`. Дальше всё адресуется по имени (§9а.9); номера строк
даны по рабочей копии на `267a82e` и служат ориентиром, а не адресом.

**`ФАКТ 1`.** `MappingDialog.__init__`, строка 125: `self.table.itemChanged.connect(self._on_edit)`.

**`ФАКТ 2`.** `_on_edit` (строки 286–318) на **каждом** из трёх своих путей заканчивается
вызовом `self.reload()`:

| Путь | Строка | Что происходит |
|---|---|---|
| ячейка очищена | 300 | `self.reload()` + `return` |
| привязка записана | 318 | `self.reload()` |
| домен отказал | 317 → 318 | `kit.show_error(...)`, затем `self.reload()` |

**`ФАКТ 3`.** `reload` (188–227) перестраивает **весь** виджет: `setRowCount(len(...))` и
четыре `setItem` на строку, плюс `self.drawing.set_drawing(drawing)` — то есть повторное
декодирование чертежа группы. `setItem` **удаляет** прежний `QTableWidgetItem`, включая тот,
который Qt только что передал в слот аргументом.

**`ФАКТ 4`.** Флаг `_loading` поднимается на строке 212 и опускается на 219 **без `try/finally`**.
Любое исключение внутри цикла заливки (`position_label`, `STATE_LABELS[...]`, `_canon_cell`)
оставляет флаг поднятым навсегда. С этого момента `_on_edit` выходит по первому же условию
(строка 294), и **диалог перестаёт записывать привязки, ничего не сообщая оператору**. После
наряда `0031` необработанное исключение стало окном (`src/ui/crash.py`) — окно оператор увидит,
а вот что окно оставило диалог глухим, не увидит никто. Это ровно тот отказ, ради которого
`crash.py` и заводился: система работает, молчит и не делает.

**`ФАКТ 5`.** `_loading` — **единственный** флаг такого рода в `src/ui`. Остальные шесть мест
программной заливки пользуются `blockSignals` (адреса — во «Входе»). **Ни одно из семи не
отказоустойчиво:** ни у одного нет `try/finally`, и у `blockSignals` последствие то же по форме
и мягче по существу — виджет остаётся глухим к сигналам до конца жизни окна.

## 2. Механизм отказа — `[INFERENCE]`, не проверено исполнением

Опасен не сам слушатель `itemChanged` — запись по действию ратифицирована S3 и остаётся.
Опасно то, что **обработчик сносит и пересобирает виджет, находясь внутри эмиссии его сигнала**.
Достижимый путь — не гипотетический, он проходит через кнопку, которую оператор нажимает
каждый раз:

```
finish()                        # нажали Done
  └─ _commit_open_editor()      # строка 243
       ├─ table.commitData(editor)        # 261 → модель меняется → itemChanged
       │    └─ _on_edit(item)             # слот внутри эмиссии
       │         └─ reload()              # setRowCount + setItem: прежние item уничтожены,
       │                                  # индекс редактора больше ничему не соответствует
       └─ table.closeEditor(editor, ...)  # 262 — закрываем редактор, которого уже нет в модели
```

Ниже границы Python ↔ C++ это удаление объекта, чей метод ещё на стеке. Класс тот же, что у
стоп-дефекта раскрытия (`0028`, доводка 2) и у самореференсного расчёта раскладки (§9а.15):
величина, которую функция задаёт, входит в её же вход. Отличие в цене — там процесс умирал без
трассы, здесь исход зависит от того, что Qt успеет тронуть после эмиссии, и потому **невоспроизводим
по расписанию**. Именно поэтому наряд не требует «воспроизвести падение»: требование —
**убрать конструкцию**, а не дождаться её проявления (волт `_system/RULES.md` §16 — причина
прежде обхода).

Побочно тем же вызовом: чертёж группы декодируется заново при каждом введённом номере
(`ФАКТ 3`). На приёмку это не выносится, но при построчном обновлении (§4, шаг 2) уходит само.

## 3. Почему 720 зелёных тестов об этом молчат — `ФАКТ`, полный счёт

Счёт сделан по **всем 31** файлам `tests/*.py`, без `head` и без ограничения выдачи
(`worklog/README.md`, «отрицательное утверждение требует полного счёта»):

| Что искали | Совпадений |
|---|---|
| `QTest.keyClicks` | **0** |
| `commitData` | **0** |
| `openPersistentEditor` | **0** |
| `QTest.*` всего | 11 (`mouseClick` 9, `keyClick` 1, `mouseDClick` 1) |

**Ни один тест приложения не вводит значение через настоящий редактор ячейки.** Все тесты
привязки (`test_ui_cg.py`, 614–966) правят модель напрямую —
`dialog.table.item(0, LOCAL_NUMBER).setText("12")`. При таком входе
`self.table.viewport().focusWidget()` пуст, `_commit_open_editor` выходит на строке 260, и
ветка `commitData` **не исполняется вовсе**. Тест `test_done_counts_what_was_typed_without_enter`
(908) назван по этой ветке и до неё не доходит.

Это §9а целиком: проверка входит в систему там же, где в неё входит человек. Оператор входит
через делегат; тесты входят через модель; между этими двумя входами и живёт дефект.

## 4. Что сделать

**Шаг 0. Входной контроль.** Проверить каждый путь «Входа». Прогнать
`tools/worktree_check.py`, сверить канон-хеш с шапкой. Снять `git status`, вписать фактический

**Шаг 1. Механизм программной заливки — в `kit`, отказоустойчивый по построению.**
Завести в `src/ui/kit/widgets.py` **контекстный менеджер** (имя на усмотрение исполнителя,
предложение — `kit.filling(widget)`), который на входе глушит сигналы виджета, на выходе
**в `finally`** возвращает прежнее состояние и **возвращает именно прежнее**, а не безусловное
`False` — вложенный вызов не должен снимать глушение внешнего. Реэкспорт в `kit/__init__.py`.

Перевести на него **все семь** мест заливки: `mapping_dialog` (`_loading` уходит совсем) и шесть
`blockSignals` из «Входа». Пройти листингом `src/ui` и **перечислить в отчёте**, что найдено и
что переведено: правило «замена механизма обязана назвать всех, кого трогает» — родня пункту
`worklog/README.md` про обязательность поля.

Флаг `_loading` после этого не должен остаться ни в одном виде — ни как поле, ни как локальная
переменная: пока он существует, существует и состояние «поднят навсегда».

**Шаг 2. Обработчик выходит из эмиссии.** `_on_edit` записывает в базу и **не перестраивает
таблицу синхронно**. Форму выбирает исполнитель, обосновав в отчёте; две очевидные:

- **(а) построчное обновление** — после записи меняются только ячейки затронутой строки
  (`State`, нормализованный `Local number`), пересчитывается `self._states` и статусная строка;
  таблица не пересобирается, чертёж не перечитывается;
- **(б) отложенная перерисовка** — `reload` уходит за границу эмиссии
  (`QTimer.singleShot(0, ...)` или эквивалент).

**(а) предпочтительна** и названа старшей: она убирает пересборку, а не переносит её во времени.
**(б) законна** как самостоятельное решение, если исполнитель покажет, чем построчное обновление
здесь хуже. Что запрещено в обеих: перестраивать виджет внутри эмиссии его собственного сигнала.

**Шаг 3. Путь «набрал → Done» остаётся целым.** После правки `_commit_open_editor` обязан
по-прежнему засчитывать набранное в открытом редакторе, а `closeEditor` — получать живой
редактор. Если порядок «сначала забрать, потом перерисовать» требует перестановки — переставить,
но смысл находки №15 (`0020`) не отменять: оператор, набравший номер в последнюю позицию и
нажавший Done, закрывает окно, а не упирается в «not finished».

**Шаг 4. Доказательство — три части, все обязательны (§9а.14).**

- **(а) структурная, платформонезависимая.** Тест, утверждающий, что за время эмиссии
  `itemChanged` таблица не пересобирается: считать вызовы `setRowCount`/`setItem`, случившиеся
  **внутри** слота, либо проверять, что `QTableWidgetItem`, переданный в слот, по возвращении
  из него всё ещё принадлежит таблице. Утверждение о **конструкции**, не о симптоме.
- **(б) настоящие события (§9а.6, §9а.19).** Тест вводит номер **через редактор ячейки**:
  одиночный клик по строке → открытие редактора → `QTest.keyClicks` → `Enter`, затем Done.
  Это первый такой тест в приложении (§3) — и он же закрывает дыру, которой все 720 зелёных
  обязаны своим молчанием.
- **(в) процесс-зонд на нативной платформе.** По образцу `tools/expansion_probe.py`: отдельный
  процесс воспроизводит последовательность «клик → набор → Enter → Done» и печатает число
  (пересборок внутри эмиссии) и код возврата. Прогнать на **старом** и **новом** коде, оба
  числа — в отчёт. Критерий «тест краснеет на старом коде» здесь неприменим напрямую (§9а.14):
  исход старого кода недетерминирован, поэтому доказательством служит **число зонда**, а не цвет.

Тесты (а) и (б) обязаны **назвать правило, которое сторожат** (§9а.10), в докстринге: «обработчик
сигнала не перестраивает свой виджет внутри эмиссии» и адрес этого наряда.

**Шаг 5. Отказоустойчивость — тестом, а не осмотром.** Тест: исключение, брошенное посреди
заливки, оставляет виджет слышащим сигналы, а диалог — записывающим. Ставится на механизм из
шага 1, то есть покрывает разом все семь мест.

### Форма шага 2 (а/б) и обоснование

Выбрана **(а) построчное обновление** — старшая по наряду, и здесь она не просто
предпочтительна, а единственная верная.

`_on_edit` после записи перечитывает состояния (`_read_states`) и обновляет **существующие**
ячейки затронутых строк через `setText`, внутри `kit.filling(self.table)`; статусную строку
пересчитывает `_show_status`. Ни `setRowCount`, ни `setItem`, ни `set_drawing`.

**Почему `setText`, а не `setItem` даже построчно.** `setItem` **уничтожает** прежний
`QTableWidgetItem`. Из обработчика `itemChanged` это означает уничтожение ровно того объекта,
который Qt передал в слот аргументом и чей метод ещё на стеке. Построчное обновление через
`setItem` убрало бы `setRowCount`, но сохранило бы **сам класс дефекта**. Отсюда правило,
которое и сторожит структурный тест: объект, пришедший в слот, обязан пережить слот.

**Почему не (б), отложенная перерисовка.** `QTimer.singleShot(0, self.reload)` вынес бы
пересборку за границу эмиссии и этим закрыл бы дефект, но оставил бы пересборку как таковую:
чертёж группы продолжал бы декодироваться на каждый введённый номер, а между вводом и
перерисовкой появилось бы окно, в котором таблица показывает одно, а база содержит другое.
(а) убирает пересборку, (б) переносит её во времени.

`reload` сохранён и по-прежнему пересобирает таблицу целиком — он зовётся **из безопасных
мест**: на открытии диалога и по нажатию `Absent from item (99)` / `Clear`, то есть вне эмиссии
`itemChanged`. Его докстринг это теперь и объявляет.

### Механизм возвращает **прежнее** состояние, а не `False` — чем проверено

Требование пункта 3(в). Подтверждено двумя независимыми способами.

**Кодом.** `finally` возвращает `was_blocked` — то, что вернул сам
`blockSignals(True)`, то есть состояние **до** вызова; константы `False` в механизме нет:

```python
previous = [widget.blockSignals(True) for widget in widgets]
try:
    yield
finally:
    for widget, was_blocked in zip(widgets, previous):
        widget.blockSignals(was_blocked)
```

**Исполнением.** Прямая проба на живых виджетах (`QTableWidget` и `QComboBox`), четыре случая:

| Случай | Ожидалось | Получено |
|---|---|---|
| обычный ход | `False → True → False` | `False → True → False` |
| **вложенность**: выход из внутреннего `with` | внешнее глушение **сохранено**, `True` | `True` |
| выход из внешнего | `False` | `False` |
| исключение изнутри | виджет слышит, `False` | `False` |
| несколько виджетов разом | оба глушатся и оба возвращаются | `True True → False False` |

То же зафиксировано тестом `test_filling_restores_the_widget_even_when_it_raises`
(`tests/test_ui_kit.py`), который проверяет все четыре случая и потому покрывает разом все семь
мест заливки: механизм один.

**Почему это не педантизм.** Верни `finally` безусловное `False` — и внутренний `with`,
закончившись, открыл бы сигналы **посреди внешней заливки**. Отказ стал бы тише прежнего:
не «виджет глух навсегда», а «виджет слышит там, где не должен», то есть обработчик действия
сработал бы на отрисовку. Проверяется поэтому именно вложенность, а не только `finally`.
