# Наряд 0003 — CG-редактор с чертежом + маппинг (S3)

- **Задача / цель:** `QMS-013` (S3 роадмапа). Дать канон-слою рабочий интерфейс: визуальный
  редактор группы характеристик (баллоны `g1…gN` поверх чертежа), переиспользуемый экран
  привязки размеров детали к g-позициям, код 99 («у детали этой позиции нет») и правку
  существующей группы. По итогу маппинг должен создаваться и меняться **визуально**, а не
  только сидом при заведении детали.

- **Вход (читать перед работой):**
  - `docs/model/CharacteristicGroup.md` — CG / g-позиция, маппинг, код 99, отличие от зоны.
  - `docs/model/Characteristic.md` — ключ `(item, local_number)`; состояния как отдельные
    g-позиции.
  - `docs/model/Item.md`, `docs/model/_overview.md` §6 (save flow) и шаг 5 процесса
    («канон-привязка до регистрации», R2).
  - `docs/model/_history/Session-03.md` §4 «Форма привязки детали к CG» — **первоисточник
    поведения баллонов**: клик по баллону → ввод локального номера → баллон ярко-зелёный;
    заполнение всех баллонов обязательно; «Сохранить» активна, когда все заполнены;
    строго «1 баллон = 1 локальный размер = 1 привязка».
  - `docs/architecture.md` §4–§5 (слои, физсхема rev 0.1), `docs/decisions.md` (R2, R3,
    ратификации S1).
  - Готовый код S1/S2: `src/db/models.py`, `src/domain/*`, `src/ui/*`, `tests/*`.
  - Волт (read-only): `_system/INFRASTRUCTURE.md` §8 — локаль рабочей машины (cp1255).

## Решения Cowork, принятые к этому наряду

Приняты в сессии QMS-013 по вопросам, которых канон не покрывал. Синхронизация канона
(`docs/decisions.md`, `architecture.md` §5, `model/CharacteristicGroup.md`, `docs/specs/`) —
за Cowork, отдельной правкой; **исполнителю канон править не нужно**.

1. **Редактор — баллоны поверх картинки чертежа** (не абстрактная раскладка). У группы
   появляется чертёж, у каждой g-позиции — координаты баллона на нём.
2. **Чертёж хранится внутри базы** (двоичное поле), а не ссылкой на файл. Это осознанное
   исключение из конвенции «вложения — ссылки, не блобы» (`architecture.md` §4): чертёж —
   справочные данные канона (~20–30 групп), без него редактор нерабочий, а правило
   «бэкап = копия одного файла БД» должно остаться верным. Конвенция для вложений
   отклонений (`deviation.attachment`) не меняется.
3. **Код 99 — отдельная таблица** `item_position_absent` с парой (деталь, g-позиция).
   **Это пересмотр ратифицированного решения S1 №6** (`is_absent` на `mapping`): текущая
   схема из-за CHECK `target_xor_absent` физически не может хранить, *какой именно*
   позиции нет у детали — сохраняется только факт «чего-то нет». Канон требует пару
   `g:99` («позицию рассмотрели, у детали её нет»), поэтому флаг и CHECK убираются,
   а `mapping.g_position_id` становится NOT NULL. Данных в базе нет — переделка бесплатна.
4. **Точка входа — отдельный раздел «Группы характеристик»** в главном окне **плюс** вызов
   того же диалога привязки из карточки детали.
5. **«Ранние кнопки» формы ввода отклонения** (R2) в этом спринте **не делаются**: формы
   ввода ещё нет (S4). S3 отдаёт **переиспользуемый диалог с публичным интерфейсом вызова**;
   в S4 форма отклонения просто вешает на него кнопки. Заглушку формы отклонения не строить.
6. **Правка существующей группы — в scope**, с защитой занятых позиций (по образцу защиты
   занятых значений справочников из S2).
7. **Перепривязка занятого размера — не молча.** Если размер детали уже привязан к другой
   позиции, привязка отбивается доменной ошибкой; сменить привязку можно только явно —
   сняв прежнюю («Очистить» на баллоне).

## Что сделать

### 1. Схема rev 0.2 — одна ревизия Alembic

Одна новая ревизия поверх baseline, без переписывания baseline. SQLite ограничен в `ALTER`,
поэтому изменения существующих таблиц — через `batch_alter_table`. `downgrade` определить.

- `characteristic_group`: `+ drawing` (LargeBinary, nullable), `+ drawing_name`
  (String(255), nullable — исходное имя файла, из него определяется формат).
- `g_position`: `+ x`, `+ y` (Float, nullable) — **нормализованные координаты 0..1**
  относительно картинки; CHECK `x IS NULL OR (x BETWEEN 0 AND 1)`, аналогично `y`.
- Новая таблица `item_position_absent`: PK `absent_id`; FK `item_id` → `item`
  (ON DELETE CASCADE); FK `g_position_id` → `g_position`; `UNIQUE(item_id, g_position_id)`.
- `mapping`: убрать колонку `is_absent` и CHECK `target_xor_absent`; `g_position_id` →
  **NOT NULL**. После правки строка `mapping` означает ровно одно: «размер привязан к
  g-позиции».
- `docs/architecture.md` §5 и `docs/model/` **не править** — синхронизирует Cowork.

### 2. Домен (чистый Python, без единого импорта PySide6)

`src/domain/groups.py` — дополнить:

- `update_group(session, group, *, name)` — переименование с проверкой уникальности.
- `add_position(session, group, spec)` / `update_position(session, position, …)` —
  геометрия (`nominal`, `tol_plus`, `tol_minus`) и координаты (`x`, `y`).
- `remove_position(session, position)` — **заблокировать**, если на позицию ссылается хотя
  бы один `mapping` или строка `item_position_absent`; сообщение с числом ссылок
  (образец — защита занятого значения справочника, S2). Свободная позиция удаляется.
- `set_drawing(session, group, data: bytes | None, name: str | None)` — принимает PNG/JPEG
  (проверять **по сигнатуре файла**, не по расширению), лимит **5 МБ**; иначе доменная
  ошибка с внятным текстом. `data=None` — снять чертёж (координаты позиций при этом
  сохраняются).

`src/domain/mappings.py` — новый модуль:

- `bind(session, item, g_position, local_number)` — найти/создать характеристику
  `(item, local_number)` через существующий `get_or_create_characteristic`, создать
  `mapping` на g-позицию; если для пары (деталь, позиция) была запись «отсутствует» —
  снять её. Отбивать: (а) размер уже привязан к другой позиции (см. решение 7);
  (б) на эту g-позицию у той же детали уже привязан другой размер — «1 баллон = 1 размер».
- `mark_absent(session, item, g_position)` — код 99: снять `mapping` этой пары, если был,
  записать `item_position_absent`; идемпотентно.
- `clear(session, item, g_position)` — вернуть пару в состояние «не рассмотрено» (снять и
  привязку, и отметку отсутствия). Характеристику при этом **не удалять**.
- `binding_state(session, item, group)` → на каждую g-позицию группы одно из трёх:
  `linked(local_number)` · `absent` · `none`. Это же используется UI для раскраски баллонов.
- `items_by_position(session, g_position)` — детали, привязанные к позиции; строки
  `item_position_absent` в выдачу **не попадают** (нужно для критерия приёмки 5).

### 3. UI

- **Раздел «Группы характеристик»** (`src/ui/cg_view.py`) в главном окне, между
  «Справочниками» и «Деталями»: список групп (название, число позиций, есть ли чертёж),
  кнопки «Создать», «Редактор…», «Привязать деталь…».
- **Визуальный редактор** (`src/ui/cg_editor.py`): холст с чертежом-фоном; баллоны — кружки
  с подписью `g1…gN`, перетаскиваются мышью (координаты сохраняются нормализованными);
  боковая панель — таблица позиций (номинал, допуск ±) с правкой, «Добавить позицию»,
  «Убрать позицию», «Загрузить чертёж…», «Убрать чертёж». Сохранение — явной кнопкой.
- **Диалог привязки** (`src/ui/mapping_dialog.py`) — переиспользуемый, тот же холст:
  - клик по баллону → поле ввода номера размера детали; заполненный баллон — **ярко-зелёный**
    (Session-03 §4);
  - действие «нет у детали (99)» на баллоне → баллон помечен как отсутствующий (серый);
  - действие «Очистить» → баллон возвращается в нейтральный вид;
  - **«Сохранить» активна только когда каждый баллон получил состояние** (номер или «нет»);
  - **публичный интерфейс вызова** (например `MappingDialog.run(engine, item, group, parent)
    -> bool`), задокументированный в докстроке как точка, на которую S4 повесит «ранние
    кнопки» формы ввода отклонения.
- **Вход из детали:** в `src/ui/item_view.py` — кнопка «Привязка к канону…» для выделенной
  детали (если у детали нет группы — предложить выбрать её из списка).
- **Группа без чертежа обязана работать:** баллоны раскладываются сеткой по умолчанию,
  привязка выполняется как обычно. Отсутствие картинки не блокирует ничего.
- Форму «Добавить деталь» и справочники **не переделывать** — только точка входа выше.

## Критерии приёмки

1. **Миграция.** `alembic upgrade head` проходит и на чистой БД, и на существующей rev 0.1;
   `downgrade` определён и проходит; новых ревизий ровно одна.
2. **Чертёж.** PNG/JPEG загружается в группу и хранится в базе: после перезапуска приложения
   и после копирования **только файла БД** на другой путь картинка на месте. Не-картинка и
   файл >5 МБ отбиваются доменной ошибкой (текст для оператора, не traceback).
3. **Баллоны.** Перетаскиваются, координаты переживают перезапуск; при другом размере окна
   баллоны стоят на тех же местах чертежа (следствие нормализованных координат).
4. **Привязка.** Клик по баллону → ввод номера → баллон зелёный; сохранение пишет пары
   (деталь, номер размера) → g-позиция; повторное открытие показывает сохранённое.
5. **Код 99.** «Нет у детали» сохраняется парой (деталь, позиция); запрос «детали по
   `(cg, g_index)`» такую деталь **не возвращает** — тест на уровне домена.
6. **Полнота.** «Сохранить» неактивна, пока хоть один баллон без состояния; тест на это есть.
7. **Правка группы.** Номинал/допуск и название меняются; удаление позиции, на которую
   ссылается привязка или отметка «нет у детали», заблокировано сообщением с числом
   ссылок; свободная позиция удаляется.
8. **Переиспользование.** Диалог привязки открывается и из раздела «Группы характеристик»,
   и из карточки детали; публичный интерфейс вызова задокументирован (S4 вешает кнопки).
9. **Слоение.** В `src/domain/**` и `src/db/**` нет импортов PySide6 — прежняя AST-проверка
   зелёная, тест-на-тест сохранён.
10. **Регресс S2.** Номер размера при сиде CG остаётся пустым и обязательным (это уже
    сделано в S2 — **не переделывать**, закрыть тестом).
11. **Тесты.** Прежние 87 зелёные + новые на всё перечисленное; `pytest` целиком зелёный.
12. **Глазами.** Прогон приложения исполнителем + рендер экранов редактора и диалога в PNG
    и проверка bidi (иврит/латиница/знаки `±` в RTL-окне не переставляются).

## Заметки исполнителю

- **А. Координаты — нормализованные 0..1, не пиксели.** Пиксельные координаты ломаются при
  смене размера окна и при замене чертежа на скан другого разрешения.
- **Б. Замена чертежа не должна ронять баллоны:** координаты остаются, оператор поправит их
  перетаскиванием. Так же и при «Убрать чертёж».
- **В. cp1255 на рабочей машине** (`INFRASTRUCTURE` §8): `*.ini` держим ASCII-only; CLI-скрипты
  в начале переключают `stdout`/`stderr` на UTF-8.
- **Г. Изолят `U+2068…U+2069`** (`ui.common.iso`) — на все LTR-строки со знаками и подписи
  `g1…gN`, печатаемые в RTL-окне рядом с ивритом; в S2 этим лечился разворот допуска `±`.
- **Д. GUI-тесты** — offscreen, как в S2; плюс рендер в PNG для глазной проверки (критерий 12).
- **Е. Миграция SQLite** — `batch_alter_table` для снятия `is_absent`/CHECK и перевода
  `g_position_id` в NOT NULL.
- **Ж. Если по ходу вскроется, что решение 3 (отдельная таблица) ломает что-то в уже
  написанном коде S1/S2** — не обходить молча, зафиксировать в отчёте.

  12. **Глазами.** Отрисовал раздел групп, редактор и диалог привязки на реальной платформе
      Qt: RTL-зеркалирование верное, иврит на чертеже и в справочнике рисуется корректно
      рядом с латиницей, `g1…gN` и `№12` не переставляются.

  **Что вскрылось прогоном и починено:**

  - **Миграция падала на `DROP TABLE g_position`** — `batch_alter_table` пересоздаёт таблицу,
    а наш `PRAGMA foreign_keys=ON` не даёт удалить таблицу, на которую ссылается `mapping`.
    `env.py` теперь выключает FK **на событии `connect`** и проверяет `foreign_key_check`
    после. Первая попытка — выключить через `exec_driver_sql` после `connect()` — сделала
    хуже: открылась неявная транзакция, Alembic перестал владеть коммитом, и миграция
    **молча откатывалась**, оставляя базу на прежней ревизии.
  - **Строки старого кода 99 не переживали `NOT NULL`** на `g_position_id`. Конвертировать их
    нечем — флаг не хранил позицию (ровно та причина, по которой решение 3 и принято), —
    поэтому миграция удаляет их с явным сообщением в консоль. На пустой базе это ни на что не
    влияет; если где-то есть рабочая копия с 99-ми, их придётся ввести заново диалогом.
  - **Домен возвращал призраков.** `session.delete(mapping)` оставлял
    `characteristic.mapping` указывать на удалённую строку, и «Очистить → привязать заново»
    падало с «размер уже привязан». Удаление идёт через коллекции владельца
    (`delete-orphan`), граф в памяти остаётся согласованным.
  - **Bidi в редакторе:** `-0.05` рисовался как `0.05-`. Ячейки редактируемые, поэтому одного
    изолята мало — `parse_optional_number` снимает изоляты перед разбором.
  - **`prepare_database` сверял набор таблиц.** Сейчас сработало случайно (rev 0.2 добавила
    таблицу); миграция, добавляющая только колонку, прошла бы незамеченной, и приложение
    работало бы на устаревшей схеме. Теперь сравнивается ревизия с head — плюс три теста.
  - Мелочь для протокола: скрипт съёмки экранов падал с segfault на
    `QBuffer(QByteArray())` — временный `QByteArray` освобождается, пока буфер им
    пользуется. Кода репозитория не касается (мы картинки только читаем), но приём
    пригодится, когда что-то начнём сохранять.

- **Отклонения / вопросы Cowork:**

  1. **Заметка Ж — что задело решение 3.** Пересмотр кода 99 задел ровно три места, все
     обновлены в том же коммите: синтетика (`src/seed/synthetic.py` — теперь пара «деталь,
     позиция»), три теста S1 на прежние «три состояния маппинга» (переписаны на новую таблицу
     и на `NOT NULL`), round-trip и счётчик таблиц 14 → 15. Кода S2 изменение не задело —
     `seed_cg_characteristics` всегда создавал маппинг с позицией.
  2. **`docs/architecture.md` §5 и `docs/model/` не трогал** — как и предписано. К
     синхронизации: 15-я таблица `item_position_absent`, поля `characteristic_group.drawing` /
     `drawing_name`, `g_position.x` / `y`, снятые `mapping.is_absent` и CHECK, `g_position_id`
     стал NOT NULL. Плюс ратификация S1 №6 в `decisions.md` теперь неверна — её нужно пометить
     пересмотренной, иначе реестр решений противоречит схеме.
  3. **Чертёж в базе — цена.** PNG-скан на 3–4 МБ × ~25 групп даст файл БД под 100 МБ. Для
     копирования это нормально, но полная выгрузка теперь тянет блобы. Если захотите держать
     базу лёгкой — вариант «чертёж в отдельной таблице с ленивой загрузкой»; сейчас не делал,
     не усложняя без нужды.
  4. **Замена чертежа не переносит баллоны.** Координаты сохраняются (как и просили), но если
     новый скан снят в другом кадрировании, баллоны окажутся не на своих местах — оператор
     переставит вручную. Автоматически совместить два скана нечем; фиксирую как известное
     поведение, не как дефект.
  5. **Диалог привязки пишет в базу сразу по действию**, а «Сохранить» лишь закрывает окно,
     подтверждая полноту. Так работает проверка полноты (§4 требует активности кнопки по
     факту заполнения) и так переживает случайное закрытие уже введённое. Если нужно, чтобы
     «Отмена» откатывала весь сеанс привязки, — это отдельная транзакция на диалог, скажите.
  6. **Правило «1 баллон = 1 размер» шире канона.** Session-03 §4 явно требует одну привязку
     на баллон; я так же запретил один размер детали на две позиции (это следует из
     `UNIQUE(characteristic_id)` в схеме, но теперь ещё и объясняется оператору текстом).
     Если для состояний (до/после электрополировки) когда-нибудь понадобится один размер на
     две g-позиции — упрёмся в схему, не только в домен.
  7. **Кнопка «Привязка к канону…» в разделе «Детали»** при отсутствии группы у детали
     предлагает выбрать любую из существующих. Это моя трактовка «если у детали нет группы —
     предложить выбрать её из списка».
