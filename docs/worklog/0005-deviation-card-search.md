# Наряд 0005 — Карточка отклонения + поиск прецедентов L1/L2 (S5)

- **Задача / цель:** `QMS-015` (S5 роадмапа) — **главный deliverable Этапа 1**. Дать рабочий
  экран одного отклонения, который сам показывает, случалось ли такое раньше, что тогда
  решили и как обосновали. Точный поиск (L1) по паре «деталь + размер» и по канонической
  g-позиции; описательный (L2) по зоне и типу отклонения. Плюс перенос диалога решения в
  карточку, снятие `N+1` на списках и закрытие Q-09 (сторож зеркала по хешу).

- **Вход (читать перед работой):**
  - `docs/model/DeviationCard.md` — карточка как ключевой deliverable, что показывается
    автоматически.
  - `docs/model/Search.md` — уровни поиска; **единица выдачи всегда отклонение целиком**,
    даже когда совпал один размер.
  - `docs/model/CharacteristicGroup.md` — канон, g-позиция, правило «1 баллон = 1 размер»,
    код 99 не поисковый ключ.
  - `docs/model/Finding.md`, `docs/model/Deviation.md`, `docs/model/Inspection.md`,
    `docs/model/reference/reference-data.md` (зона и тип — метки для описательного поиска).
  - `docs/model/_overview.md` §6 и шаги 6–8 процесса (прецеденты → исследования → решение).
  - `docs/specs/deviation-entry.md` — **as-built S4**, особенно §5 (диалог решения), §6
    (исследования, зеркальный поиск) и §8 (известные пределы: `N+1`, кнопки исследований).
  - `docs/specs/cg-editor-and-mapping.md` — `MappingDialog.run(...)`.
  - `docs/architecture.md` §5 (**схема rev 0.2**), `docs/decisions.md` (ратификации S1–S4).

## Решения Cowork, принятые к этому наряду

1. **Карточка — отдельное окно**, а не переработка формы S4. Открывается кнопкой
   «Карточка…» из списка отклонений и **сама всплывает после сохранения нового
   отклонения** (канон: «opens as soon as a deviation is entered»). Форма регистрации S4 не
   переписывается — она принята и покрыта тестами.
2. **Прецеденты показываются по выбранной находке.** Сверху карточки — таблица находок
   отклонения; выбор строки перерисовывает панель прецедентов. Отклонение с пятью
   размерами не сваливает разное в одну кучу, инженер смотрит конкретный размер.
3. **В выдачу попадают только отклонения с внесённым решением.** Прецедент существует ради
   готового решения и обоснования; нерешённое отклонение подсказать ничего не может.
   Следствие принято осознанно: свежие однотипные случаи, ещё не дошедшие до решения, в
   карточке не видны.
4. **Кнопка «Решение…» остаётся и в списке отклонений, и в карточке.** Диалог
   `DecisionDialog` переезжает **как есть** (S4 сделал его самостоятельным ровно для
   этого); список сохраняет короткий путь, когда решение уже известно.
5. **L2 — всегда вторая вкладка**, рядом с «Точные (L1)». Если L1 пуст, карточка
   открывается сразу на L2. Так видно, что описательный поиск вообще есть.
6. **L1 показывается двумя секциями:** «Эта деталь, тот же размер» и «Другие детали, та же
   позиция `gN`». Сила совпадения читается структурой экрана, а не колонкой.
7. **Раздел «Поиск» в навигации остаётся выключенным.** Самостоятельный экран поиска — это
   конструктор запросов Этапа 1.5 (S8, `docs/model/Search.md` → deep search). S5 ищет
   только от отклонения, которое на руках.
8. **Q-09 — перенос зеркала:** генератор пишет **артефакт внутрь репо**, в волт его
   переносит Cowork через мост. Claude Code в волт не ходит (INFRA-013), ручной шаг
   пользователя не вводится.
9. **Порядок для Q-09.** Реворд `docs/model/Characteristic.md` под ратификацию S1 №1
   (`state_depending` — self-FK) делает **Cowork** до начала этой части наряда — канон
   слой Cowork. Claude Code берёт канон **как он есть на момент работы** и генерирует
   артефакт из него.

## Что сделать

### 1. Домен — прецеденты (чистый Python, без импортов PySide6)

Новый модуль `src/domain/precedents.py`. Схему **не трогать** — всё выражается запросами
поверх rev 0.2 (S4 доказал, что это возможно: `inspections_for` обошлась без новых столбцов).

**Строка выдачи** — `@dataclass(frozen=True) PrecedentRow`: всё, что рисует таблица, одним
запросом (образец — `DeviationRow` из `deviations.py`, включая агрегатный счётчик
исследований). Поля: `deviation_id`, `dev_number`, `date`, `item_id`, `item_number`, `wo`,
`quantity`, `local_number`, `g_label` (`«CG · g5»` либо `None`), `direction`, `value`,
`dimension_point`, `zone`, `deviation_type`, `decision`, `explanation`, `decision_date`,
`inspection_count`, `match` (чем совпало — см. ниже).

- `precedents_same_dimension(session, characteristic, *, exclude_deviation=None)` — **L1a**:
  находки по этой же характеристике (та же деталь, тот же номер размера). Отклонение
  текущей карточки исключается; берутся только отклонения с непустым `decision_dev`.
  Сортировка — свежие сверху (`date DESC`, затем `dev_number DESC`).
- `precedents_same_position(session, characteristic, *, exclude_deviation=None)` — **L1b**:
  через `characteristic.mapping` берём g-позицию; находим характеристики **других деталей**,
  привязанные к той же позиции, и их находки. Своя деталь исключается — иначе дублирует
  L1a. Отметки «нет у детали» (код 99, `item_position_absent`) в выдачу **не входят**:
  код 99 не поисковый ключ (`CharacteristicGroup.md`; ровно так уже устроен
  `mappings.items_by_position`). Если у размера привязки нет — вернуть пустой список,
  **без ошибки**: это штатное состояние, а не сбой.
- `precedents_descriptive(session, *, zone=None, deviation_type=None, exclude_deviation=None,
  exclude_characteristic=None)` — **L2**: находки, у которых совпала зона **или** тип
  отклонения. Поле `match` принимает три значения — `zone+type` / `zone` / `type`;
  сортировка — сначала совпавшие по обоим, дальше по дате. Строки, уже попавшие в L1 по
  тому же размеру, из L2 исключаются (`exclude_characteristic`), чтобы вкладки не
  повторяли друг друга. Если у находки не заполнены ни зона, ни тип — вернуть пусто; UI
  скажет об этом словами (см. §2).
- `canon_labels(session, characteristics) -> dict[int, str]` — **пакетный** запрос состояния
  канона по набору размеров, **один** запрос на набор. Заменяет построчный вызов в форме
  отклонения (`docs/specs/deviation-entry.md` §8, `N+1`). Значения — те же три
  достижимых состояния, что ратифицированы в S4 (`g5` / «не привязан» / «размер ещё не
  заведён»); «нет у детали (99)» среди них нет по построению.
  **Форму отклонения S4 перевести на этот вызов** — это и есть закрытие Δ S4-а.

Экспорт новых имён — через `src/domain/__init__.py`, как заведено.

### 2. UI — карточка отклонения

Новый `src/ui/card_dialog.py`; раздел «Карточка отклонения» в навигации **не заводить**
(карточка всегда открывается от конкретного отклонения).

- **Шапка (только чтение):** бизнес-номер, деталь, WO, машина, количество, дата, NCR,
  вложение, решение (или «решение не принято») + обоснование. Кнопки: **«Править…»**
  (открывает существующую `DeviationDialog` на правку и по возврату перечитывает карточку),
  **«Решение…»** (существующий `DecisionDialog`, **без переделки**), «Закрыть».
- **Таблица находок** — колонки как в форме S4 (номер размера, канон, направление,
  величина, точка, зона, тип, число исследований). Выбор строки управляет всей нижней
  частью. Кнопки: **«Исследование…»** и **«Привязать к канону…»** — обе активны **по
  выбранной строке**, а не по «в таблице есть строки» (закрытие Δ S4-в). «Привязать к
  канону…» зовёт `MappingDialog.run(...)`; после возврата колонка «канон» и секция L1b
  перечитываются — привязка ровно затем и нужна, чтобы поиск по позиции заработал.
- **Панель прецедентов — две вкладки:** «Точные (L1)» и «Похожие (L2)».
  - L1 — две озаглавленные секции с числом строк в заголовке: «Эта деталь, тот же размер
    (N)» и «Другие детали, та же позиция `gN` (N)». Если размер не привязан к канону —
    вторая секция показывает не пустую таблицу, а строку-объяснение: «размер не привязан к
    канону — поиск по позиции недоступен» и кнопку «Привязать к канону…».
  - L2 — одна таблица с колонкой «совпало по» (зона / тип / оба). Если у находки не
    заполнены ни зона, ни тип — вместо таблицы строка-объяснение, что описательный поиск
    опирается на эти два поля.
  - **Если L1 пуст, карточка открывается на вкладке L2.**
- **Колонки прецедента:** номер отклонения, дата, деталь, WO, размер (и `gN`, если есть),
  направление и величина, решение, обоснование (в одну строку, полностью — во всплывающей
  подсказке), число исследований.
- **«Открыть прецедент…»** (и двойной клик по строке) — открывает карточку того отклонения
  поверх текущей. Никаких ограничений глубины не вводить; окно закрывается своей кнопкой.
- **Автооткрытие:** после успешного сохранения **нового** отклонения из формы карточка
  открывается сама. При правке существующего — не открывать.
- **Вход из списка отклонений:** кнопка «Карточка…» + двойной клик по строке.

### 3. Q-09 — сторож зеркала по содержимому (`tools/build_mirror.py`)

Сейчас сторож сверяет `source_version` зеркала с `rev` канона, а `rev` поднимается руками:
пропустили подъём — сторож зелёный, зеркало устарело. Лечим тем, что сторож перестаёт
зависеть от ручного поля.

- **Штамп хеша.** Генератор считает `sha256` по набору канон-файлов (те же файлы, что он и
  собирает, — с `canon: true`), в порядке сортировки по пути относительно `docs/model/`, с
  **нормализацией переводов строк** (`CRLF → LF`) перед хешированием — иначе checkout на
  Windows даст другой хеш на том же содержимом. Хеш пишется в frontmatter зеркала полем
  `source_hash: "sha256:…"`; `source_version` остаётся как есть (человеку читать).
- **Режим проверки.** `python tools/build_mirror.py --check <путь-к-зеркалу>` — пересчитать
  хеш канона, сравнить с `source_hash` в файле, напечатать вердикт, код возврата `0`/`1`.
  Проверка **не должна** требовать записи. Отдельно приложить в вывод список файлов,
  вошедших в набор, — чтобы расхождение можно было объяснить, а не только констатировать.
- **Артефакт вместо записи в волт.** Добавить `--out build/mirror/CONCEPT_full_rev1.00_EN.md`
  как штатный путь прогона (создать каталог при отсутствии) и внести `build/` в
  `.gitignore`, если его там нет. **В волт не писать** — файл оттуда заберёт Cowork.
- Прогнать генератор на текущем каноне, оставить артефакт на диске и **назвать его путь и
  хеш в отчёте** — по ним Cowork перенесёт зеркало и сверит.
- Протокол в `docs/_INDEX.md` (раздел про зеркало) обновить одним абзацем: сторож — по
  хешу, регенерация — артефактом, перенос — Cowork.

## Критерии приёмки

1. **Карточка открывается** из списка (кнопка + двойной клик) и **сама** — после сохранения
   нового отклонения; при правке существующего не открывается.
2. **Прецеденты по выбранной находке:** смена строки в таблице находок перерисовывает обе
   вкладки; при пустом выборе панель показывает подсказку, а не пустые таблицы.
3. **L1a** находит прошлое отклонение по паре (деталь, размер) и **не показывает текущее**.
4. **L1b** находит отклонение **другой** детали, привязанной к той же g-позиции; своя
   деталь в этой секции не дублируется; деталь, помеченная кодом 99, в выдачу не попадает.
5. **Только решённые.** Отклонение без решения в выдачу L1/L2 не попадает — тест на паре
   «решённое + нерешённое» по одному размеру.
6. **L2** находит по зоне и по типу отдельно и вместе; колонка «совпало по» верна;
   совпавшие по обоим стоят выше; строки того же размера, показанные в L1, в L2 не
   повторяются. При пустых зоне и типе — объяснение вместо таблицы.
7. **Вкладка по умолчанию:** при пустом L1 карточка открывается на L2 (тест на состоянии
   экрана, не на глаз).
8. **Нет `N+1`.** Число SQL-запросов при отрисовке списка прецедентов и таблицы находок
   **не растёт** с числом строк: тест считает запросы (перехват `before_cursor_execute`) на
   наборе из 2 и из 20 находок — числа совпадают. Форма отклонения S4 переведена на
   `canon_labels` и покрыта тем же счётчиком.
9. **Решение из карточки** проходит тем же путём, что из списка: `DecisionDialog` **не
   изменён** (проверить diff'ом — файл не должен появиться в изменённых), `approved` без
   обоснования по-прежнему отбивается, дата решения перезаписывается.
10. **Кнопки по выбору строки:** «Исследование…» и «Привязать к канону…» неактивны, пока
    строка не выбрана (закрытие Δ S4-в). После привязки колонка «канон» и секция L1b
    обновляются без переоткрытия карточки.
11. **Схема rev 0.2 не меняется** — ни таблиц, ни колонок, ни ревизий миграции. Если
    окажется, что чего-то не хватает — **стоп и вопрос в отчёт**, не правка схемы.
12. **Слоение.** `src/domain/**` и `src/db/**` без импортов PySide6 (прежняя AST-проверка);
    находки по-прежнему создаются только через `make_finding`.
13. **Q-09.** `--check` даёт зелёный на свежесгенерированном зеркале и **красный** после
    правки любого канон-файла без подъёма `rev` — это и есть смысл всей затеи, покрыть
    тестом (правку канона в тесте делать во временной копии, не в `docs/model/`).
14. **Тесты.** Прежние 233 зелёные + новые на всё перечисленное.
15. **Глазами.** Прогон приложения + рендер карточки (обе вкладки, обе секции L1) в PNG на
    нативной платформе: RTL верный, величины со знаком и `gN`-подписи не переставляются.
