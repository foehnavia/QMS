## 1. Кросс-поиск по канону — это чинится первым

**Что неверно сейчас.** `precedents_same_position` исключает свою деталь строкой
`ItemRevision.item_id != characteristic.revision.item_id`. Прогон: у `C1-10375A` позиция
`g13` в ревизии `A` привязана к номеру `19`, в `B` — к `66`. Отклонения есть по обеим.
Секция по номеру не находит (номер переехал), секция по канону выбрасывает свою деталь —
прецедент не показан нигде.

**Что сделать.**

- Убрать исключение по детали. Секция канона возвращает **все** совпадения по g-позиции —
  чужие детали и **другие ревизии своей детали**.
- Вместо этого исключать **то, что уже показала соседняя секция**: тот же размер той же
  ревизии. Механизм есть — `_exclude(..., exclude_characteristic=...)`, сохранённый при
  снятии описательного уровня (наряд `0022`); он для этого и сохранялся.
- Дубля быть не должно: если номер **не** переезжал, совпадение придёт в секцию по номеру и
  в канонную попасть не имеет права.
- **Заголовок секции обязан совпасть с содержимым.** Сейчас он обещает `Other items` и
  начнёт врать. Предлагается `Same canon position g13 — other items and other revisions`;
  точная формулировка на усмотрение исполнителя, требование одно: заголовок не обещает
  меньше, чем секция отдаёт.
- Пустое состояние и надпись «only deviations that already carry a decision are listed»
  остаются.

**Тесты (обязательно все три):**

1. номер переехал между ревизиями, размер канонный → прецедент **найден** канонной секцией,
   строка несёт пометку другой ревизии;
2. номер не переезжал → прецедент показан **ровно один раз**, секцией по номеру;
3. чужая деталь по той же g-позиции — как было, без регрессии.

## 2. Знак `!` — одно значение

`!` означает **ровно одно** на всех экранах: *номер прочитан против другой ревизии, и
опереться, кроме номера, не на что.*

| Случай | Пометка строки | `!` |
|---|---|---|
| прошлая ревизия, размер **канонный** | да | **нет** |
| прошлая ревизия, размер **не-канонный** | да | да |
| текущая ревизия | нет | нет |

Проверить, что канонный размер из прошлой ревизии `!` **не получает** — сейчас это не
проверено ни одним тестом, а после правки §1 такие строки впервые появятся в выдаче.

## 3. Карточка детали — новый экран

- Вход: **двойной щелчок** по строке `Items` (сейчас открывает привязку — это неверно) и
  новая кнопка **`Card`** в таблице.
- Содержимое: номер детали, `Item type`, `Connection type`, `Size class`. **Только чтение**;
  правка — кнопкой `Edit…`, открывающей нынешнюю форму правки (симметрия с карточкой
  отклонения).
- Таблицы привязок внутри карточки **нет** — есть **ссылка/кнопка**, делающая то же, что
  `Mapping…`, для **выбранной в карточке ревизии**.
- Кнопка `Mapping…` в таблице `Items` **остаётся** — прямой вход в частую операцию.

## 4. Ревизия в карточке: просмотр и назначение — разные органы управления

- **Выпадающий список ревизий — только просмотр.** Показывает всю ленту (`A`, `B`, …),
  переключает то, что показано, и **ничего не пишет в базу**. Действующая помечена в списке.
- **Смена действующей ревизии — отдельная кнопка** («Set as current»), и она **обязательно**
  закрыта подтверждающим окном: «сделать ревизию X действующей?» с последствием в одну
  строку (новые отклонения будут регистрироваться против неё).
- Основание: показ не должен уметь менять состояние, а смена действующей — редкое действие с
  последствиями, которое не должно случаться от промаха мышью.
- При переключении показа меняется только то, чем ревизия владеет: набор размеров и привязки.
  `Item type`, `Connection type`, `Size class` принадлежат детали и не меняются.

## 5. Список отклонений детали

- **Фильтров не делать** — они часть общей фильтровой машинерии (часть 2 `Q-14`, после S6).
  Сейчас требуется только сам список.

## 6. Ревизия там, где виден номер детали

- Карточка отклонения — ревизия в шапке, рядом с `Item`, **только чтение**. Менять — через
  `Edit`, где она уже есть и работает правильно (наряд `0024`, менять не надо).
- Правило, по которому проверять остальные экраны: **номер детали без ревизии — дефект.**

## 7. Общие таблицы — правка только через `Edit`

- В таблицах, которые **показывают** (`Items`, `Deviations`, справочники), правка внутри
  строки запрещена: строка там — запись, и один промах заменяет содержимое ячейки символом.
  Правка — явным открытием формы.
- **Диалоги, существующие ради ввода, не затрагиваются.** В привязке набор локального номера
  прямо в строке — ратифицированное решение S3 (запись по действию; `Done` лишь подтверждает,
  что ни одна позиция не осталась нерешённой), и транзакция на весь сеанс тогда была отвергнута
  осознанно. Там строка — поле ввода, а не чужая запись. Ничего в привязке не менять.
- Пройти по существующим таблицам и снять редактируемость там, где она осталась с прошлых
  спринтов; в дымовой тест добавить проверку, что ячейка списка не входит в режим правки по
  двойному щелчку.
