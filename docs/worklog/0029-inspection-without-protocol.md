## 1. Схема и миграция `rev05`

| Поле | Было | Станет |
|---|---|---|
| `no_protocol` | нет | новое, `Boolean` NOT NULL, **по умолчанию 0** |
| `protocol` | `Text` NOT NULL | **nullable** |
| `conclusion` | `String(500)` nullable | без изменений в объявлении; обязательность даёт инвариант |

**Инвариант держит `CHECK`, а не форма.** Смысл: запись, не несущая ни файла, ни вывода,
невидима для поиска прецедентов — то есть бесполезна ровно в том, ради чего таблица заведена.
Форму можно обойти импортом, скриптом или следующим нарядом; ограничение схемы обойти нельзя.

```
(no_protocol = 0 AND protocol IS NOT NULL AND trim(protocol) <> '')
OR
(no_protocol = 1 AND (protocol IS NULL OR trim(protocol) = '')
                 AND conclusion IS NOT NULL AND trim(conclusion) <> '')
```

Отмеченная галочка требует **пустого** протокола намеренно: «файл есть, но он не нужен» —
состояние без смысла, и допускать его значит заводить третий случай, который придётся
объяснять на каждом экране.

**Перенос существующих строк:** у всех есть протокол → `no_protocol = 0`, ограничение проходят
без правки данных. Проверить это тестом, а не предположением.

**Откат.** Строки с `no_protocol = 1` в старой схеме непредставимы (там `protocol` NOT NULL, а
у них его нет). Удалять **с громким сообщением**, по прецеденту `rev04` и `rev02` — и по тому
же доводу: подставить выдуманный путь к файлу означало бы вписать в базу документ, которого не
существует. Снять `CHECK` перед изменением значений, как в `rev04`.

## 2. Доменный слой

- `create_inspection` / `update_inspection` принимают `no_protocol`. Значений по умолчанию у
  `update_inspection` **не появляется** (`CLAUDE.md` §9).
- Валидация — **доменная, с человеческим текстом**, поверх схемного ограничения. Ограничение
  ловит любой путь записи; доменная проверка объясняет оператору, что не так, вместо
  `IntegrityError`:
  - галочка снята → протокол обязателен (как сейчас);
  - галочка отмечена → протокол обязан быть пуст, **вывод обязателен**;
  - текст отказа называет, чего именно не хватает, — не «нарушено ограничение».
- Существование файла протокола по-прежнему **не проверяется** (решение 4 реестра).

## 3. Форма исследования

- Галочка **`No protocol`** под полем протокола, **снята по умолчанию**.
- Отмечена → поле пути и кнопка выбора файла **блокируются и очищаются**; подпись поля
  `Conclusion` получает признак обязательности.
- Снята обратно → поле протокола снова активно и пусто; введённый вывод не теряется.
- Порядок на форме не меняется: тип → позиция → вывод → протокол → галочка.

## 4. Карточка отклонения

В секции исследований запись без протокола читается как полноценная: тип, позиция, вывод.
Кнопка открытия протокола для неё **неактивна** — и это не отказ, а отсутствие файла; если
неактивная кнопка без объяснения выглядит поломкой, поставить рядом приглушённую пометку
`No protocol`. Решает исполнитель по снимку, а не по предположению.

## Критерии приёмки

1. `worktree_check.py` → `VERDICT: OK`; `canon hash HEAD` вписан и совпал с ожидаемым.
2. Полный прогон зелёный (`--ignore`/`-k` — только после первого полного прохода), число
   названо. На входе 631.
3. **Тест ограничения схемы:** запись без протокола и без вывода **отвергается на уровне базы**
   — попытка вставки в обход домена не проходит. Это главный тест наряда: он проверяет
   инвариант, а не форму.
4. **Тест:** галочка отмечена + вывод → сохраняется; галочка отмечена без вывода → отказ с
   человеческим текстом; галочка снята без протокола → отказ.
5. **Тест миграции:** накат на базе с существующими строками не теряет строк и проставляет им
   `no_protocol = 0`; откат описан, работает, и строки с `no_protocol = 1` удаляются с
   сообщением.
6. **Тест формы настоящими событиями** (§9а.6): клик по галочке блокирует поле протокола и
   очищает его; повторный клик возвращает поле активным. Не вызовом метода — кликом.
7. Снимок формы с отмеченной галочкой — в `build/screens/`.
8. **Прогон руками (пользователь):** завести исследование типа `Tolerances review` с отмеченной
   галочкой и выводом, сохранить, увидеть его в карточке и в раскрытии списка.
