# 0016 — редактор группы теряет введённое при «Add position» / «Remove position»

> Наряд цикла QMS-016. Ветка `run/qms-016`, в `main` не писать ничего.
> Основание — журнал `docs/worklog/0006-run-qms-016.md`, находка **№9** (прогон, шаг 4).
> Пользователь **продолжает прогон** с обходом (сохранять после каждой строки), останова нет.

## 1. Цель

В редакторе группы (`src/ui/cg_editor.py`) значения, набранные в таблице, живут **только в
ячейках** `QTableWidget`; список `self._rows` несёт то, что было прочитано из базы при
`reload()`. Любое действие, зовущее `_refresh()`, перерисовывает таблицу из `self._rows` и тем
**затирает набранное**.

Пять точек вызова (`cg_editor.py:157, 191, 196, 201, 223`) — то есть теряется не только на
«Add position»:

| Действие | Что происходит сейчас |
|---|---|
| `add_position` | новая строка добавлена, **все набранные значения стёрты** |
| `remove_position` | строка снята, **набранное в остальных стёрто** |
| `load_drawing` | чертёж загружен, **набранное стёрто** |
| `drop_drawing` | чертёж снят, **набранное стёрто** |
| `reload` | штатно: читаем из базы заново |

Обход, которым пользователь идёт сейчас: «Save» после каждой позиции. Для группы из
пятнадцати выносок это пятнадцать открытий редактора.

**Почему это дефект, а не задумка.** Правило наряда 0003 «правки копятся в форме и уходят
одной транзакцией по Save» означает, что до Save ничего не записано в **базу**, — а не что
форма вправе терять набранное между двумя нажатиями внутри себя.

## 3. Что сделать

- Перед любой перерисовкой, **кроме `reload()`**, забирать набранное из ячеек в `self._rows`.
- **Забор не должен падать на недобранном значении.** Оператор может нажать «Add position»,
  когда в ячейке стоит `0.` или `−` — это не ошибка ввода, это середина набора. Значит в
  строке хранится **сырой текст**, а разбор в число остаётся там, где он и был: в `_collect()`
  на «Save», где ошибка ввода и должна называться.
- Индекс `g_index` и `position_id` при заборе не трогаются: индекс выдаётся формой и в ячейке
  только читается.
- `load_drawing` / `drop_drawing` забирают набранное так же: смена чертежа к значениям
  отношения не имеет.
- `reload()` остаётся единственным местом, которое **намеренно** перечитывает значения из базы
  поверх набранного (это возврат к записанному, а не побочный эффект).

## 4. Чего НЕ трогать

- Правило «одна транзакция по Save» — запись в базу по-прежнему только на «Save».
- Гард занятости позиции при удалении (проверка на клике).
- Неизменяемость `g_index`, выдачу `max + 1`, инвариант «верхнее ≥ нижнего».
- Схему, миграции, `main`.

## 5. Критерии приёмки

1. Набрать значения в первой строке → «Add position» → **значения первой строки на месте**,
   новая строка пустая с индексом `max + 1`.
2. Набрать значения в трёх строках → «Remove position» на второй → значения первой и третьей
   на месте.
3. Набрать значения → загрузить чертёж → значения на месте; то же на снятии чертежа.
4. Недобранное значение (`0.`, `−`, пусто) переживает «Add position» и не поднимает ошибку;
   ошибка ввода по-прежнему называется на «Save».
5. «Save» после серии добавлений и удалений пишет ровно то, что видно на экране.
6. Тесты зелёные, число назвать явно (было 427).

## 6. Отчёт исполнителя

### Входной контроль

Все четыре пути раздела «Вход» проверены **до начала работы** и существуют:
`docs/worklog/0006-run-qms-016.md` · `src/ui/cg_editor.py` · `src/ui/cg_dialog.py` ·
`tests/test_ui_cg.py`. Останова не потребовалось.

### Сделано

**Строка формы носит сырой текст.** `_Row` больше не хранит `float | None`, а хранит текст
ячейки как есть. Это и есть ответ на требование «забор не должен падать на недобранном
значении»: `0.`, `−` и пустое живут в форме сколько угодно, потому что их никто не разбирает
до «Сохранить».

**Появился `_take_typed()`** — забор набранного из ячеек в `self._rows`: текст как есть, без
разбора и проверок. `g_index` и `position_id` не трогаются (индекс выдаёт форма, в ячейке он
только читается; `position_id` в таблице не живёт вовсе).

**Четыре точки вызова забирают набранное перед перерисовкой:** `add_position`,
`remove_position` (до снятия строки — иначе набранное в остальных вернулось бы к прочитанному
из базы), `load_drawing`, `drop_drawing`. `reload()` остался единственным местом, которое
затирает набранное **намеренно**, и это записано в его докстроке.

**Разбор в число остался ровно там, где был** — в `_collect()` на «Сохранить». Он теперь
сперва зовёт `_take_typed()`, поэтому читать ячейки во второй раз ему не нужно: источник
один. Результат разбора уехал в отдельный тип `_Spec` — в форме `nominal` это текст `0.`, в
домене `None` или число, и держать два смысла под одним именем дороже, чем объявить второй
тип. Запись в базу по-прежнему только на «Сохранить», одной транзакцией.

**`_refresh()`** получил докстроку с обязательством зовущего: сперва забрать набранное. Дефект
был именно такого рода — перерисовка верна сама по себе, но стоит на пути самого частого
действия оператора.

### Замеченное по ходу — Cowork

1. **`0.` разбирается в `0.0` и ошибкой не является.** Наряд перечисляет `0.` среди
   недобранных значений; по факту `float("0.")` = 0.0, поэтому на «Сохранить» такая ячейка
   пройдёт как ноль, а не как ошибка. На поведение правки это не влияет (до «Сохранить» её
   всё равно никто не разбирает), но в критерии 4 ошибку называет соседняя ячейка — одинокий
   `−`. Тест написан по факту.
2. **Снимки не пересоздавал:** экран не изменился ни одной подписью, ни одной колонкой —
   правка целиком во внутреннем состоянии формы. Скажите, если снимок всё равно нужен.
3. **Соседние формы с таблицей — что я посмотрел по коду.** Дефект был в паре «набранное
   живёт только в ячейках + перерисовка из списка, прочитанного при открытии». Три формы с
   таблицей рядом:
   * `cg_dialog` — **чист**: сплошной перерисовки нет вовсе, `add_row` / `drop_row` /
     `set_position_count` трогают только свои строки; это уже закреплено тестом
     `test_shrinking_the_count_drops_rows_from_the_tail`.
   * `deviation_dialog` — **нечего терять**: таблица находок только для чтения, значения
     вводятся в отдельном диалоге и живут в списке формы, а не в ячейках.
   * `item_dialog` — **под вопросом на прогоне**: колонка локальных номеров редактируемая, и
     `reload_positions()` её очищает. Но зовётся она только когда меняется **сам набор
     позиций** (форма открыта, выбрана другая группа, группа заведена на лету) — то есть тот
     же намеренный случай, что и `reload()` здесь. Из кода дефекта не вижу; проверять этот
     путь стоит руками на шаге «новая деталь».
