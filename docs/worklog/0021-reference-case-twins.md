# 0021 — близнецы по регистру в справочниках: свести и не плодить

> Наряд цикла QMS-016. Ветка `run/qms-016`, в `main` не писать ничего.
> Основание — журнал `docs/worklog/0006-run-qms-016.md`, находка **№22**.
> **Блокирующая: порча данных базы прогона.** Шаги 14–18 на такой базе давали бы ложный
> результат по поиску прецедентов.

## 1. Что в базе (ФАКТ, снимки экрана Reference data)

**Item type — 8 значений, из них три пары различаются только регистром:**

| Значение | Ссылок | Близнец | Ссылок |
|---|---|---|---|
| `Abutment` | — | `abutment` | — |
| `Drill` | **1** | `drill` | — |
| `Implant` | — | `implant` | **2** |

Плюс `Connect Abutment` (1 ссылка) и `Straight Multy-Unit` (—).

**Deviation type — 12 значений, шесть пар:** `Angle`/`angle`, `Cutting-edge width`/`cutting-edge
width`, `Inner diameter`/`inner diameter`, `Thread burr`/`thread burr`, `Thread length`/`thread
length`, плюс `Outer diameter` (**1 ссылка**) и `Inner bore depth`.

**Обе стороны пар используются записями.** Деталь `MT-SD1037A` держит тип `Drill` (заглавная),
детали `C1-10375A` и `C1-14375A` — `implant` (строчная). Находка отклонения `0001` ссылается на
`Outer diameter`, находка `0002` — на `inner diameter`.

## 2. Почему это блокирующая находка, а не косметика

Тип отклонения — **один из двух ключей описательного поиска L2** («зона ИЛИ тип»). Пока
`Thread burr` и `thread burr` — два разных значения, две записи об одном и том же дефекте в
одну выдачу **не попадут никогда**, и отсутствие прецедента будет выглядеть как «такого раньше
не было». Это ровно тот отказ, ради предотвращения которого строится вся система.

То же для `Item type`: срезы по типу детали разъедутся надвое.

## 3. Причина — установить, не гадать

Наряд `0020` §3.5 требовал: «первая буква приводится к заглавной при сохранении; **уже
введённые нормализуются**». По факту в базе лежат обе формы. Возможны два объяснения, и они
чинятся по-разному:

* нормализация существующих значений **не выполнялась** (написано только приведение при
  сохранении) — тогда близнецы пришли с шага 3, от оператора;
* нормализация **завела новые строки** вместо переименования существующих.

**Установить по коду и по данным** (время создания строк, если оно есть; иначе по логике
правки) и назвать в отчёте. От ответа зависит, чинится ли только данные или ещё и код.

## 4. Что сделать

### 4.1 Свести пары в данных

Для каждой пары, различающейся **только регистром**:

1. **Выживает форма с заглавной буквы** — она соответствует правилу §3.5 наряда `0020`.
2. Все записи, ссылающиеся на близнеца, **перевешиваются** на выжившую (детали — по
   `item_type`, находки — по `deviation_type`, и так для каждого из шести списков).
3. Близнец удаляется — уже без ссылок, поэтому штатный гард «занятое значение не удаляется»
   не мешает.

**Операция доменная, не скриптовая:** `reference.merge_values(session, model, keep, drop)` с
проверками — оба значения из одного списка, различаются только регистром либо слияние явно
разрешено вызывающим, `keep != drop`. Скрипт разовой правки не годится: то же понадобится при
импорте `.xlsx` (S6), где регистр придёт из чужой таблицы.

### 4.2 Закрыть источник

Приведение регистра при сохранении и **регистронезависимая** проверка дубля уже сделаны
нарядом `0020` (`find_value` через `casefold`, `ensure_value`). Проверить, что:

* переименование значения (`Edit`) идёт через ту же проверку — иначе близнец заводится правкой,
  а не созданием;
* сид справочников не создаёт значение, отличающееся регистром от существующего;
* нормализация существующих, если её не было, **выполняется как переименование**, а не как
  добавление.

### 4.3 Отчёт о том, что сведено

В отчёте — таблица: список · выжившее значение · удалённый близнец · сколько записей
перевешено. Это данные прогона, и оператор должен видеть, что именно с ними сделали.

## 5. Чего НЕ трогать

- Схему, миграции, `main`.
- Значения, различающиеся не только регистром (`Inner diameter` и `Inner bore depth` — **разные
  типы**, не близнецы).
- Аббревиатуры: `NP`, `C1`, `SP`, `IntHex`, `Coni.Con` — правило первой буквы их не касается и
  слияние им не грозит.
- Ширины таблиц — они в доводке наряда `0020` §7.

## 6. Критерии приёмки

1. В каждом из шести списков **нет двух значений, различающихся только регистром** —
   проверяется запросом, а не глазами.
2. Ни одна запись не потеряла ссылку: число деталей с типом и число находок с типом до и после
   совпадает.
3. `Drill` и `implant` из базы прогона сведены; итоговый тип у `MT-SD1037A`, `C1-10375A`,
   `C1-14375A` назван в отчёте явно.
4. Повторное заведение близнеца невозможно ни созданием, ни правкой, ни сидом.
5. `merge_values` — доменная операция с тестами, а не разовый скрипт.
6. Тесты зелёные, число назвать явно (было 476).

## 7. Отчёт исполнителя

`docs/worklog/0006-run-qms-016.md` · `src/domain/reference.py` · `src/seed/reference.py` ·
`src/app.py` · `tests/test_domain_reference.py` · `data/qms016.sqlite`. Все на месте.

### Установленная причина

Установлена **по коду и по идентификаторам строк**, а не по догадке. Оба объяснения §3 верны, но
решающее — второе, и оно не то, на которое падало подозрение.

**1. Нормализация существующих значений не выполнялась.** `normalise_case` была написана
нарядом `0020`, но **не звалась ниоткуда**: `grep normalise_case src/ tools/` давал одно
определение и ни одного вызова. Приведение работало только при сохранении нового значения.

**2. Сид дописывал близнеца при каждом запуске.** `seed_reference` сверял имена **точно**:

```python
existing = set(session.scalars(select(model.name)))
missing = [name for name in names if name not in existing]
```

После `0020` сид стал приводить свои значения к заглавной, а сверял по-прежнему точно — поэтому
`Thread burr` не находил `thread burr` и дописывал рядом. Это видно по идентификаторам базы
прогона: у `ref_deviation_type` строки 1–5 — исходный сид строчными, 6–7 — добавленное
оператором, **8–12 — те же пять значений с заглавной, вставленные позже**. У `ref_zone` картина
зеркальная: 1–2 переименованы оператором в заглавные, а 5–6 — исходные строчные, вставленные
сидом обратно.

Из этого следует, что чинить надо **и данные, и код**, и что чинить код одним приведением
регистра было бы мало: пока сверка точная, близнец возвращается на следующем запуске.
