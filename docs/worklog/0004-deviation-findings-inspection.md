# Наряд 0004 — Отклонение + Находки + Исследование (S4)

- **Задача / цель:** `QMS-014` (S4 роадмапа). Дать ручной ввод **полной записи отклонения**:
  шапка (WO / NCR / количество / дата / машина / вложение), находки `1..N` по размерам с
  ранней привязкой к канону (R2), решение `decisionDev` отдельным действием, исследования
  `0..N` на находке. После S4 база наполняется руками от начала до конца — без карточки и
  поиска (это S5) и без импорта Excel (S6).

- **Вход (читать перед работой):**
  - `docs/model/Deviation.md` — атрибуты, 4 исхода, WO, NCR, три уровня количества,
    граница области базы.
  - `docs/model/Finding.md` — поля находки, привязка через характеристику, зона и тип.
  - `docs/model/Inspection.md` — когда заводится строка, привязка к находке **и** к паре
    (Item, размер), независимость `decisionInsp`, «наука в протоколе».
  - `docs/model/reference/reference-data.md` — зона и тип отклонения заполняются
    оператором при вводе; большинство справочных данных заводится по ходу, а не заранее.
  - `docs/model/_overview.md` §6 и шаги 3–8 процесса; `docs/model/Characteristic.md`.
  - `docs/architecture.md` §5 (**схема rev 0.2**), `docs/decisions.md` (ратификации S1, R2,
    решения S3).
  - `docs/specs/cg-editor-and-mapping.md` — публичный вход `MappingDialog.run(...)`, на
    который вешаются «ранние кнопки».
  - Готовый код: `src/domain/findings.py` (`make_finding`), `src/domain/mappings.py`,
    `src/domain/characteristics.py`, `src/db/ids.py`, `src/ui/*`.

## Решения Cowork, принятые к этому наряду

1. **Решение по отклонению вносится отдельным действием**, не в форме регистрации. Форма
   регистрирует отклонение с пустым решением (`decision_dev` nullable — ратификация S1 №2);
   решение вносится кнопкой «Решение…» из списка отклонений. Это порядок канона:
   регистрация — шаг 3, решение — шаг 8, после изучения прецедентов. В S5 то же действие
   переедет в карточку отклонения без переделки — вынести его в отдельный диалог.
2. **Исследование заводится действием на выбранной находке** («Исследование…» в таблице
   находок), список исследований отклонения виден в нижней части окна. Отдельного раздела
   «Исследования» не делаем: цель исследования — конкретная находка, и выбор её руками из
   общего списка добавляет только шанс промахнуться.
3. **Отклонение без находок не сохраняется** — минимум одна (канон: `1..N`). Отклонение без
   размера невидимо для поиска прецедентов, то есть бесполезно.
4. **Вложение** (`deviation.attachment`) — многострочное поле, одна ссылка на строку, плюс
   кнопка «Выбрать файл…», вставляющая путь строкой. Файлы **не копируются** в базу:
   исключение про блобы касается только чертежей CG (`architecture.md` §4).
5. **Деталь выбирается в форме** из списка, рядом — кнопка «Создать деталь…» (существующая
   `ItemDialog`). Это тот же ранний путь, что и привязка к канону: `_overview.md` §6 прямо
   допускает заведение детали в момент обработки отклонения.

## Что сделать

### 1. Домен (чистый Python, без импортов PySide6)

`src/domain/deviations.py` — новый модуль:

- `register(session, *, item, wo, quantity, date, machine=None, ncr=None, attachment=None)`
  — создать отклонение с бизнес-номером (существующий `db.ids`), **без решения**.
  Валидации: WO непустой; `quantity` целое ≥ 1; дата не в будущем; деталь обязательна.
- `set_decision(session, deviation, *, decision, explanation, ncr=None, decision_date=None)`
  — внести/сменить решение. Проверки:
  - `decision` ∈ 4 значениях словаря (`approved` / `rejected` / `sorting` / `repair`);
  - **`explanation` непусто при `approved`** — доменная валидация, отложенная с S1 (№3):
    на одобрении обоснование уходит в `אישור חריגה`, пустым быть не может;
  - `decision_date` по умолчанию — системное время (уже в модели).
- `list_deviations(session, *, item=None)` — список для экрана, с числом находок.
- `delete_deviation(session, deviation)` — удаление вместе с находками и исследованиями
  (каскад уже в схеме); отдельного подтверждения в домене не изобретать, спрашивает UI.

`src/domain/findings.py` — дополнить:

- `update_finding(session, finding, *, direction, value, dimension_point, comment, zone,
  deviation_type)` — **все поля обязательны** в подписи (правило S3: функция заменяет
  запись целиком, пропущенный аргумент не должен выглядеть как «не трогаем»).
- `remove_finding(session, finding)` — **заблокировать удаление последней находки**
  отклонения (инвариант `1..N`) и находки, на которой висит исследование (сообщение с
  числом ссылок, образец S2/S3).
- `make_finding` — не переписывать; это единственная точка создания находки.

`src/domain/inspections.py` — новый модуль:

- `create_inspection(session, finding, *, inspection_type, decision_insp, protocol)` —
  бизнес-номер `INSP-…` из `db.ids`; `decision_insp` ∈ (`approved`, `not_approved`);
  отклонение выводится из находки, отдельно не передаётся. Тип — из справочника
  `ref_inspection_type`.
- `update_inspection` / `remove_inspection` — по тому же правилу «целиком».
- `inspections_for(session, item, characteristic)` — зеркальный поиск «все исследования по
  паре (Item, размер)». Пара **выводится** через находку (`finding → characteristic →
  item`), отдельных полей в схему не добавлять — это и есть «явная привязка к паре» канона
  на текущей схеме; проверить запросом, а не новым столбцом.

### 2. UI

- **Раздел «Отклонения»** (`src/ui/deviation_view.py`): список — номер, деталь, WO, дата,
  количество, решение (или «не принято»), число находок, число исследований. Кнопки:
  «Добавить отклонение…», «Открыть…», «Решение…», «Удалить».
- **Форма отклонения** (`src/ui/deviation_dialog.py`) — регистрация и правка:
  - шапка: деталь (выбор + «Создать деталь…»), WO, машина, количество, дата, NCR,
    вложение (многострочное + «Выбрать файл…»);
  - **таблица находок** с кнопками «Добавить находку…», «Править…», «Убрать»,
    «Исследование…»; колонки: номер размера, канон (`g5` / «нет у детали» / «не привязан»),
    направление, величина, точка, зона, тип отклонения, число исследований;
  - **ранние кнопки (R2)** рядом с находкой: «Привязать к канону…» — зовёт
    `MappingDialog.run(engine, item_id, cg_id, parent)`; активна, когда деталь выбрана.
    Если у детали нет группы — та же логика выбора, что в разделе «Детали»;
  - сохранение — **одной транзакцией** по «Сохранить»: отклонение и его находки; пустой
    список находок кнопку блокирует (решение 3), причина видна текстом.
- **Диалог находки** (`src/ui/finding_dialog.py`): номер размера (с автосозданием
  характеристики доменной функцией, если такого размера у детали ещё нет), направление
  `+`/`−` (обязательно), величина, точка, комментарий, зона, тип отклонения (оба — из
  справочников, пусто допустимо). Показывать состояние привязки размера к канону.
- **Диалог решения** (`src/ui/decision_dialog.py`): 4 исхода списком с человеческими
  подписями, обоснование (`explanation`), NCR, дата решения. Отдельный виджет — в S5 он
  переезжает в карточку как есть.
- **Диалог исследования** (`src/ui/inspection_dialog.py`): тип из справочника, вердикт
  (одобрено / не одобрено), протокол (ссылка на документ), показ находки, к которой
  привязано.
- Разделы «Карточка отклонения» и «Поиск» остаются неактивными пунктами навигации (S5).

## Критерии приёмки

1. **Регистрация.** Отклонение создаётся с бизнес-номером, без решения; в списке видно
   «решение не принято». Обязательные поля отбиваются доменными сообщениями, не
   `IntegrityError`.
2. **Находки.** Добавляются, правятся, удаляются; **последняя не удаляется** (сообщение);
   размер, которого у детали нет, создаётся автоматически доменной функцией.
3. **Гард (перенос из S2).** Находки создаются **только** через `make_finding` — проверка
   разбором кода (AST): в `src/ui/**` нет прямого конструирования `Finding(...)`, плюс
   тест-на-тест, что проверка ловит настоящее нарушение. Инвариант «находка ∈ деталь
   отклонения» покрыт через UI-путь, а не только доменным тестом.
4. **Ранняя привязка (R2).** Из формы отклонения открывается тот же `MappingDialog`;
   после привязки колонка «канон» в таблице находок показывает g-позицию без
   переоткрытия формы.
5. **Решение.** Вносится отдельным действием; 4 исхода пишутся; **`approved` без
   обоснования отбивается**; смена решения перезаписывает дату решения.
6. **Исследование.** Заводится на выбранной находке, `0..N` на отклонение; бизнес-номер
   уникален; `decision_insp` не влияет на `decision_dev` (тест: одобренное исследование
   при отклонённом отклонении — валидная комбинация).
7. **Зеркальный поиск.** `inspections_for(item, characteristic)` возвращает исследования по
   паре (Item, размер) — тест на двух деталях с одинаковым номером размера: выдачи не
   смешиваются.
8. **Целостность.** Удаление отклонения уносит находки и исследования; удаление находки с
   исследованием заблокировано.
9. **Слоение.** `src/domain/**` и `src/db/**` без импортов PySide6 — прежняя AST-проверка
   зелёная.
10. **Схема.** rev 0.2 **не меняется**: ни новых таблиц, ни колонок, ни ревизий миграции.
    Если по ходу окажется, что чего-то не хватает, — **стоп и вопрос в отчёт**, не правка.
11. **Тесты.** Прежние 151 зелёные + новые на всё перечисленное.
12. **Глазами.** Прогон приложения + рендер формы отклонения, диалога находки и диалога
    решения в PNG: RTL верный, величины со знаком не переставляются, иврит в справочниках
    рисуется корректно.

## Заметки исполнителю

- **А. Количество.** Значение `9999` означает «выборка `X מתוך Y`» и приходит из импорта
  (S6). В ручном вводе — обычное число; отдельного флага не заводить (это флаг на S6,
  `decisions.md`).
- **Б. Направление обязательно** (`direction` NOT NULL, из слова max/min источника).
  Качественные признаки (`GO`, пин) на этапе 1 живут в `comment` — поле направления при
  этом всё равно требуется, оператор выбирает знак осознанно.
- **В. `dimension_point`** в поиске не участвует — это индекс точки замера, хранится и
  показывается, не более.
- **Г. Зона и тип отклонения** заполняются оператором и чистятся администратором; в форме
  это обычные выпадающие списки справочников, пустое значение допустимо.
- **Д. cp1255** на рабочей машине: `*.ini` — ASCII-only, CLI-скрипты → UTF-8 stdout
  (`INFRASTRUCTURE` §8).
- **Е. GUI-тесты** — offscreen, как в S2/S3; плюс рендер в PNG для глазной проверки.
- **Ж. Область базы кончается решением.** Судьба деталей после решения (сортировка → QC,
  повторные циклы, комитет по отклонениям) в базе не моделируется — не достраивать.
