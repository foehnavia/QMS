# Наряд 0002 — S2 · Каркас Qt + справочники + Item

- **Задача / цель:** **QMS-012** (спринт **S2** плана Этапа 1, [[ROADMAP_MIS-QMS]] §S2). На
  выходе — запускаемое GUI-приложение на **PySide6** поверх готового слоя хранения S1: главное
  окно с навигацией и RTL/bidi «из коробки», CRUD-экраны всех справочников, форма «Добавить
  деталь» (классификаторы с `General`-дефолтом), сид CG-размеров при заведении детали и создание
  CG на лету (R3), доменный сервис автосоздания не-CG характеристики. Плюс доменная проверка
  инварианта «находка ∈ деталь отклонения» — перенос из ревью S1 (`docs/decisions.md`,
  2026-08-11: критерий приёмки S2). **Полного** ввода отклонений/находок/исследований, карточки,
  поиска, ETL и генерации документов в этом наряде **НЕТ** — это S3+ (см. «Чего не трогать»).

  - `docs/model/Characteristic.md` — ключ `(item, local_number)`; автосоздание не-CG при первом
    отклонении; спящее поле R1 (не трогать).
  - `docs/model/CharacteristicGroup.md` — CG/g-позиция + **Mapping**; создание CG на лету (R3);
    ранний маппинг (R2); код 99; отличие CG от зоны.

    находка↔деталь → доменная проверка S2; Item↔CG m:n не материализовать).
  - **Готовый код S1** (на нём стоим, не переписывать): `src/db/models.py` (14 моделей, словари
    `GENERAL`/`DECISION_*`/`Direction`, `REFERENCE_MODELS`), `src/db/session.py`
    (`session_scope`, `PRAGMA foreign_keys=ON`, URL из `QMS_DB_URL`/`app.sqlite`),
    `src/seed/reference.py` (`seed_reference`, `ref()` — доступ к `General`), `src/db/ids.py`,
    наряд `docs/worklog/0001-foundation.md` (отчёт S1 — принятые решения по схеме).

- **Что сделать:**

  1. **Окружение и раскладка.** Работать в существующем venv `C:\MIS-QMS\.venv` (PySide6 6.11
     проверен в Ф2, `architecture.md` §9). Держать домен **UI-независимым** (§4): предложение —
     `src/domain/` (сервисы поверх `src/db`), `src/ui/` (виджеты PySide6), `src/app.py` (точка
     входа). **`src/domain/**` не импортирует PySide6.** Фактическую раскладку зафиксировать в
     отчёте. БД — та же `app.sqlite` через `src/db/session.py` (движок/сессии не дублировать).

  2. **Скелет приложения (PySide6).** Главное окно; RTL/bidi-раскладка приложения из коробки
     (`QApplication` layout direction = RightToLeft); навигация между разделами **«Справочники»**
     и **«Детали»**. Разделы карточки/ввода отклонения/поиска — **не** строить (заглушка или
     отсутствуют). Точка входа запускается как GUI (`python -m ...` или `src/app.py`).

  3. **CRUD справочников — все 6** (`REFERENCE_MODELS`: `ref_item_type`, `ref_connection_type`,
     `ref_size`, `ref_zone`, `ref_deviation_type`, `ref_inspection_type`). Экран(ы) списка с
     добавлением / переименованием / удалением. **Удаление под защитой** (заметка В):
     значение, на которое ссылается FK, удалить нельзя (внятное сообщение, не каскад);
     `General` в `connection_type`/`size` — структурный дефолт, неудаляем/непереименуем.
     Идемпотентный стартовый сид (`seed_reference`) — переиспользовать, не дублировать.

  4. **Форма «Добавить деталь».** Поля: `item_number` (обяз., UNIQUE — дубль показать понятной
     валидацией, а не сырым `IntegrityError`); `item_type` (необяз., из `ref_item_type`);
     `connection_type` и `size` (обяз., выпадающие; **предвыбран `General`**). Сохранение создаёт
     `Item`.

  5. **Сид CG-размеров при заведении детали + CG на лету (R3).** В форме детали — привязка к
     существующей CG: по её g-позициям (`g1…gN`) засеять характеристики детали + маппинги на
     соответствующие `g_position` (принадлежность к CG выводится через
     `characteristic → mapping → g_position → cg`; **отдельную Item↔CG таблицу не заводить** —
     `decisions.md`). Присвоение `local_number` при сиде — **заметка Б**. Создание **CG на лету**
     (R3) — простой формой: имя CG + строки g-позиций (`g_index`, `nominal`, `tol_plus`,
     `tol_minus`); новая CG доступна для привязки. **Визуальный редактор с «шариками» — это S3,
     здесь его НЕТ**; в S2 достаточно функционального ввода.

  6. **Автосоздание не-CG характеристики — доменный сервис.** `get_or_create` по
     `(item, local_number)`: есть — вернуть; нет — создать характеристику **без формы, без CG,
     без маппинга** (`_overview.md` §6, `Characteristic.md`). Идемпотентно (подстраховано
     `UNIQUE(item_id, local_number)`). Реальная точка вызова — форма ввода отклонения (S4);
     в S2 достаточно сервиса + теста (по желанию — отладочный триггер в UI). — **заметка Г**.

  7. **Доменная проверка инварианта «находка ∈ деталь отклонения»** (перенос ревью S1,
     `decisions.md` 2026-08-11). Сервис-гард: при связывании находки с отклонением проверять
     `characteristic.item_id == deviation.item_id`, иначе отклонять с внятной ошибкой. UI находок —
     S4; гард живёт в домене уже сейчас, покрыт юнит-тестом.

  8. **Тесты (pytest).** Домен — юнитами (сид/удаление под защитой, создание детали + сид CG,
     CG на лету, `get_or_create`, гард инварианта). GUI — offscreen-smoke
     (`QT_QPA_PLATFORM=offscreen`), конструирующий главное окно и формы без падения
     (заметка Е). Прогон на чистой БД (та же baseline-миграция S1).

  9. **Git.** Осмысленными порциями (скелет+навигация / справочники / форма детали + сид CG /
     домен-сервисы + гард / тесты); сообщение — что и зачем + ссылка на **QMS-012 / наряд 0002**.
     `.gitignore` S1 не ослаблять (`app.sqlite`, `.venv/` не коммитить).

- **Критерии приёмки (проверяемые):**
  1. **GUI стартует** (`python -m …`/`app.py`); приложение в **RTL**-раскладке; ивритский текст в
     полях/таблицах рисуется корректно (bidi). Проверка: ручной запуск исполнителем + offscreen-
     smoke конструирует окно и формы без исключений.
  2. **Деталь создаётся** формой: `item_number` + классификаторы (`General` по умолчанию у
     `connection_type`/`size`); повторный `item_number` отклоняется понятной валидацией (UNIQUE).
  3. **Сид CG:** при привязке детали к CG её g-позиции засеяны как характеристики + маппинги на
     `g_position` (проверяемо в БД: у детали появились `characteristic` с `mapping.g_position_id`).
  4. **CG на лету (R3):** новую CG (имя + g-позиции с номиналом/допуском) можно создать из потока
     заведения детали и сразу привязать.
  5. **Автосоздание не-CG:** `get_or_create(item, local#)` создаёт характеристику без формы и без
     маппинга; повторный вызов дублей не плодит (тест).
  6. **Справочники (все 6) правятся из UI:** добавление/переименование/удаление; удаление
     FK-занятого значения заблокировано; `General` неудаляем/непереименуем (тест на защиту).
  7. **Инвариант находка↔деталь:** попытка связать находку с характеристикой **чужой** детали
     отклоняется гардом (тест).
  8. **Домен UI-независим:** в `src/domain/**` нет импорта PySide6 (проверяемо тестом/grep).
  9. **pytest зелёный**; ручной прогон приложения исполнителем — ок.

- **Чего не трогать:**
  - `docs/model/**`, `docs/architecture.md`, `docs/decisions.md`, `docs/staging.md`,
    `docs/_INDEX.md` — **канон / авторский слой Cowork**. Не править; расхождение канона с кодом
    не чинить молча — в «Отклонения / вопросы Cowork».
  - **Схема БД заморожена (rev 0.1, 14 таблиц).** Никаких новых таблиц/колонок и **никаких новых
    Alembic-миграций** в S2. Если UI реально упирается в отсутствие поля — **стоп, вынести
    вопросом**, не мигрировать молча. В частности: Item↔CG «многие-ко-многим» **не
    материализовать** (принадлежность к CG — через `characteristic→mapping→g_position→cg`);
    спящее `state_depending` (R1) не заполнять.
  - **Вне scope S2, не реализовывать:** визуальный CG-редактор с «шариками» и переиспользуемый
    UI маппинга + «ранние кнопки» в форме ввода (**S3**); полный ввод отклонения / находок /
    исследований (**S4**); карточка-представление + автообзор прецедентов + поиск L1/L2 (**S5**);
    ETL Excel/regex (**S6**); генерация `אישור חריגה`/PDF (**S7**); deep-query (**S8**).
    (`architecture.md` §7, `docs/staging.md`.)
  - Волт (подключён read-only) — не писать.
  - `mcp__claude_ai_FHA*` — запрещено (`deny` в репо `.claude/settings.json`).

- **Заметки исполнителю (не блокеры; решение зафиксировать в отчёте):**
  - **А. Слоение UI / домен.** `architecture.md` §4: ядро UI-независимо, UI — единственный
    сменный слой. Держать сервисы в `src/domain/` поверх `src/db`, PySide6 — только в `src/ui/`.
    Это страхует будущую замену/тестируемость и требуемый критерий 8. Раскладку — в отчёт.
  - **Б. Локальные номера при сиде CG.** Характеристике нужен `local_number` (номер размера с
    чертежа детали); маппинг `(item, local#) → g_position` назначает человек. Выбери минимальный
    путь для S2 (оператор вводит `local#` на каждую g-позицию при заведении, **либо** дефолт =
    `g_index` с возможностью правки) и обоснуй. **Геометрию не выдумывать:** `nominal`/`tol_plus`/
    `tol_minus` живут на `g_position` (CG) и на характеристику не копируются. Богатый визуальный
    маппинг — S3.
  - **В. Политика удаления справочника.** FK-занятое значение — блокировать (не каскад), сообщать
    оператору. `General` (`connection_type`/`size`) — неудаляем/непереименуем. Поведение — в отчёт.
  - **Г. Автосоздание не-CG.** Доменный сервис `get_or_create(item, local#)`, без формы
    (`_overview.md` §6, `Characteristic.md`). Боевой вызов — форма ввода отклонения S4; в S2 —
    сервис + тест (+ по желанию отладочный триггер). Идемпотентность подстрахована UNIQUE.
  - **Д. Локаль машины cp1255** ([[INFRASTRUCTURE]] §8, из наряда 0001): точка входа и любой
    CLI-скрипт перенастраивают `stdout`/`stderr` на UTF-8 (иначе печать иврита/кириллицы →
    `UnicodeEncodeError`); новые `*.ini` держать ASCII-only.
  - **Е. Тест GUI без дисплея.** Для прогона без экрана — offscreen (`QT_QPA_PLATFORM=offscreen`)
    smoke, конструирующий главное окно и формы; «живой» иврит/RTL подтверждается ручным запуском
    (критерий 1). `pytest-qt` — по желанию (доустановку зафиксировать в `requirements.txt`).
