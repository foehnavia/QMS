# Наряд 0026 — слияние `run/qms-016` в `main` + регенерация и переименование зеркала

- **Задача / цель:** `QMS-020`. Влить ветку цикла `run/qms-016` в `main` **перемоткой
  целиком** (решение **Q-11**) и **сразу за слиянием, без паузы** собрать зеркало концепта
  из нового `main` под новым именем `CONCEPT_mirror_EN.md` (решение **Q-10**). На выходе:
  `main` = вершина ветки, артефакт зеркала лежит в `build/mirror/CONCEPT_mirror_EN.md`,
  прежнее имя не осталось ни в одной строке полосы исполнителя.

- **Вход:**
  - `tools/build_mirror.py` — генератор и сторож зеркала (`--out` / `--check`)
  - `tools/worktree_check.py` — гард канон-хеша (шаг 0 входного контроля и приёмка)
  - `docs/model/_overview.md` — канон-вход, несёт `rev` для шапки зеркала
  - `docs/worklog/README.md` — цикл наряда, входной и выходной контроль
  - `CLAUDE.md` (корень репо) — конституция исполнителя, §3, §3а, §3в, §3б
  - `.gitignore` — подтверждает, что `build/` в git не попадает

- **Канон-хеш на старте:**
  `sha256:7583be9f6a81df12a9985516f04e8cd2a3c6ce22f37e450ae69401beaaf0d0bf`

  > [!warning] **Значение снято Cowork с рабочей копии на диске через мост, а не с `HEAD`.**
  > Shell на машине из облака нет, `git archive HEAD` мне недоступен ([[INFRASTRUCTURE]] §3),
  > поэтому вписанное число — это `canon hash worktree`, а не `canon hash HEAD`. Первым
  > действием прогони `python tools/worktree_check.py`: вердикт `OK` означает, что оба хеша
  > сошлись и записанное значение действительно и есть хеш `HEAD`. **Расхождение — стоп**
  > (§3в): не подгонять шапку под факт, а доложить оба числа и ждать.

- **Что сделать:**

  **0. Входной контроль (§3, §3а, §3в).** Пути «Входа» на месте? `worktree_check.py` даёт
  `OK`? Сам этот файл наряда приедет мостом Cowork **незакоммиченным** — он напечатается в
  слое `docs` справочно и вердикта не меняет (§3в: стоп-условие только `docs/model/`).
  Закоммить его первым, отдельным коммитом, до начала работ.

  **1. Слияние — перемоткой, без merge-коммита.**
  ```
  git checkout main
  git merge --ff-only run/qms-016
  git push origin main
  ```
  `--ff-only` здесь не удобство, а **гард**: если перемотка почему-то невозможна, команда
  откажет, а не сделает merge-коммит молча. Отказ — стоп-условие: доложить, что именно не
  сходится, ничего не вливать.
  **Ветку `run/qms-016` не удалять.** Указатель на ней сохраняется до отдельного решения
  Cowork; работа после наряда продолжается на `main` (остаться на `main`).

  **2. Регенерация зеркала из нового `main` — сразу, без паузы.**
  ```
  python tools/build_mirror.py --model docs/model --out build/mirror/CONCEPT_mirror_EN.md
  python tools/build_mirror.py --model docs/model --check build/mirror/CONCEPT_mirror_EN.md
  ```
  Второй вызов обязан дать `OK` (код 0). Это проверка **сборки**, а не свежести: тавтологии
  здесь нет ровно постольку, поскольку она ловит порчу записи на диск.

  **3. Прежнее имя `CONCEPT_full_rev1.00_EN.md` — полный счёт и правка своей полосы.**
  Имя файла зеркала в генераторе **нигде не зашито** — оно живёт только в `--out` и в
  примерах докстринга `build_mirror.py` (строки ≈45 и ≈48). Поэтому:
  - прогнать поиск по **всему** репозиторию, без `head`, `-m`, `--max-count` и прочих
    ограничений выдачи (`docs/worklog/README.md`, «Отрицательное утверждение требует полного
    счёта»);
  - **править только свою полосу** — `tools/`, `src/`, `tests/`. Докстринг `build_mirror.py`
    привести к новому имени;
  - всё найденное **вне** своей полосы (`docs/**`, корневой `CLAUDE.md`, `README.md`) —
    **не трогать**, а выписать списком путей и строк в отчёт. Это слой Cowork, правлю я.
  - Отдельно проверить, не завязаны ли на прежнее имя тесты и фикстуры.

  **4. Полный прогон тестов.** Целиком, без `-k` и без `--ignore` (`README.md`, «Частичный
  прогон после массовой правки проверяет не работу, а выборку»). Число тестов на входе — 546.

  **5. Коммит и отчёт.** Осмысленными порциями, со ссылкой на наряд `0026` / `QMS-020`.
  Артефакт зеркала в git **не коммитить** — `build/` в `.gitignore`.

- **Критерии приёмки:**
  1. `git rev-parse main` == `git rev-parse run/qms-016` == `c30c864489af78464785b06c726d403cde4354f6`
     **плюс** коммиты этого наряда; `git log --oneline --merges main -1` не показывает
     merge-коммита от этого слияния (перемотка состоялась).
  2. `git rev-parse origin/main` == `git rev-parse main` — слияние запушено.
  3. `python tools/worktree_check.py` → `VERDICT: OK`, и напечатанный `canon hash HEAD`
     **совпадает со значением в шапке этого наряда** (§3б п. 5, выходной контроль).
  4. Файл `build/mirror/CONCEPT_mirror_EN.md` существует; `--check` по нему → `OK`, код 0.
  5. Полный счёт упоминаний прежнего имени: в `tools/`, `src/`, `tests/` их **ноль**;
     упоминания вне этих папок перечислены в отчёте путями и строками.
  6. Полный прогон тестов зелёный, число тестов названо в отчёте.
  7. `git status` чист по `build/` — артефакт в индекс не попал.
  8. Ветка `run/qms-016` существует.

- **Чего не трогать:**
  - **`docs/model/`** — канон, слой Cowork. Наряд не меняет в нём ни строки; движение канона
    во время наряда — стоп-условие в обе стороны (§3в и §3б п. 5).
  - **Остальной doc-слой** — `docs/decisions.md`, `docs/specs/`, `docs/_INDEX.md`,

  - **Волт** — read-only, запись запрещена принудительно (§5).
  - **Перенос зеркала в волт, переименование копии в волте и правка ссылок в `code-registry`
    — не входят в наряд.** Это делает Cowork через мост (INFRA-013); наряд заканчивается
    артефактом в `build/mirror/`. Объявлено заранее, поэтому отсутствием-расхождением не

  - `app.sqlite` в корне и любые базы прогона — не трогать.
