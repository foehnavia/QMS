## 0. Где живёт дизайн-система — поправка к постановке

**Не в памяти claude.ai-проекта.** Проект MIS-QMS держит **маршрут, а не знание**: документов
в нём ноль намеренно (Repo-central). Док, положенный в память проекта, через неделю станет
четвёртой копией — ровно тот отказ, из-за которого проект и разделяли (история модели жила в
трёх местах, и ни одно не было каноном).

Канон дизайн-системы — **`docs/design/design-system.md` в репо, ветка `run/qms-016`**. Это и
есть «память»: файл под git, в одном экземпляре, виден и Cowork, и Claude Code.

**Цепочка и роли звеньев:**

| Звено | Что это | Кто ведёт |
|---|---|---|
| Канва (`.dc.html`) | витрина для человека: посмотреть, поспорить, показать | Claude Design |
| `docs/design/design-system.md` | **канон**: числа, роли, правила. Единственный источник | Cowork |
| `src/ui/kit/` | реализация: тема QSS + виджеты-компоненты | Claude Code |
| Экраны | собираются из `kit`, своих чисел не имеют | Claude Code |

Направление стрелок — вниз. Канва не выводится из кода, код не выводится из канвы: оба
сверяются со спекой. Число, встреченное в коде и не встреченное в спеке, — дефект.

> [!warning] Целевая технология — **PySide6/Qt, не веб.** «Кодовые компоненты» здесь не React,
> а подклассы и фабрики Qt-виджетов плюс тема на **Qt Style Sheets** — CSS-подобный, но
> **урезанный** язык. Дизайн-система, выпущенная в веб-допущениях, окажется нереализуемой.

## 1. Что исправить в канве

1. **Шрифт не объявлен нигде.** В файлах канвы нет ни одного `font-family`. Для нас это
   блокер, а не мелочь: приложение рисует **иврит, латиницу и цифры одной строкой**, офлайн,
   на Windows, из onefile-сборки. Требуется:
   - явный стек с ивритским покрытием, присутствующий в Windows **без установки**
     (ориентир: Segoe UI → Arial → системный по умолчанию);
   - запрет на докачиваемые шрифты — установка офлайн, из `.whl`, интернета на машине нет;
   - отдельно назван шрифт для чисел, если он отличается (табличные цифры желательны:
     в колонке величин разряды должны стоять в столбик).

2. **Реализуемость в QSS.** Каждый токен и каждое состояние обязаны быть выразимы либо в Qt
   Style Sheets, либо в коде виджета. Чего в QSS **нет**: теней (`box-shadow`),
   псевдоэлементов, анимаций перехода, произвольных полупрозрачных наложений поверх виджетов;
   градиенты — только `qlineargradient`. Если в канве такие эффекты есть — заменить на
   реализуемое (граница, фон, толщина, отступ), а не оставлять «дизайнерским намерением».

3. **Единицы и масштаб.** 11 / 12 / 13 / 16 / 28 px и метрики строк (40 / 66 / 82 у
   отклонения, 28 / 43 / 58 у находки) объявить **логическими пикселями при масштабе 100 %**
   Windows. Указать поведение при 125 / 150 %: масштабирует Qt, и ни одна метрика не должна
   быть завязана на пиксельную сетку конкретного снимка.

4. **Токены — машиночитаемо.** Отдельным блоком: `имя · значение · роль · где применяется`,
   в виде, который переносится **копированием**, а не считыванием с картинки. Это и есть то,
   что экономит токены будущим сессиям: спека генерируется из блока, а не пересматривается
   глазами. Сейчас в канве 40 ролевых имён и 44 hex-цвета — расхождение объяснить: либо
   лишние цвета получают имена, либо исчезают.

## 2. Что добавить — компоненты вместо экранов

Канва описывает **экран** списка отклонений. Дизайн-система обязана описывать **детали**, из
которых соберутся и остальные экраны прогона. Рисовать эти экраны не нужно — нужен перечень
компонентов с границами применения:

- таблица данных (плотность, высота строки, зебра, выделение, фокус);
- строка-раскрытие трёх уровней (Deviation → Finding → Inspection) — визуальный язык уровня;
- форма: подпись + поле, ширины, порядок, обязательность;
- диалог: рамка, заголовок, ряд кнопок, порядок и сторона;
- кнопки: основная, вторичная, опасная — все состояния;
- вкладка среза;
- бейдж состояния решения (пять значений, цвет + монохром);
- подсказка (hint) под контролом;
- пустое состояние — отдельно «нет данных» и «нет прецедентов» (карточка обязана объяснять
  пустоту текстом, а не показывать две пустые таблицы);
- сообщение об ошибке (модальное);
- статус-бар.

Экраны, которые из них соберутся дальше по прогону: карточка отклонения с двумя вкладками
прецедентов, форма отклонения с находками, редактор CG с баллонами поверх чертежа, диалог
привязки к канону, справочники.

## 3. Направление и bidi — раздел первого класса, из ратификаций

§7 канвы («смешанная ячейка») расширить до полного раздела. Правила уже **ратифицированы**,
выводить заново не нужно:

- **единица направления — абзац** (ячейка, строка), не виджет и не окно. Основание: снимок на
  нативной платформе — в одном текстовом поле уживаются абзацы разных направлений;
- **единица изоляции — атомарный токен**, ровно один изолят на токен. Основание: стенд
  `tools/bidi_stand.py`. Формулировка S5 не отменена — она верна для атомарного токена;
- **выравнивание**: вправо — измеренные величины (`Nominal`, `Tolerance ±`, `Sign · value`);
  влево — даты, счётчики, идентификаторы, номера;
- **шасси** (навигация, кнопки, заголовки, рамки) — жёстко LTR; ячейка и поле — по содержимому;
- **язык подписи** — English; ивритский термин допустим как **якорь цеховой лексики в
  подсказке** (`פק"ע — e.g. W26007336`), но не как единственное имя поля.

## 4. Что вернуть

1. Обновлённую канву (те же три файла).
2. **Блок токенов машиночитаемо** — см. §1.4.
3. **Перечень компонентов** по §2: для каждого — размеры, отступы, состояния, правило
   направления, границы применения.

Из этого Cowork пополняет `docs/design/design-system.md`. Спека — сжатая: числа и правила,
без пересказа картинок.

## 5. Чего не делать

- Не рисовать экраны S6–S8 (импорт `.xlsx`, упаковка) — их скоуп ещё не определён прогоном.
- Не менять термины подписей: они берутся из `docs/model/`, а не из вкуса.
- Не заводить второй язык интерфейса и не переизобретать правила направления — они выше.
- Не трогать `main`: вся работа цикла живёт в `run/qms-016`.

## 6. Критерии приёмки

1. Ни одного цвета, размера или отступа в канве, у которого нет **имени** в блоке токенов.
2. Объявлен шрифтовой стек с ивритским покрытием, доступный офлайн на Windows; названо
   поведение цифр в колонке величин.
3. Ни одного эффекта, невыразимого в QSS или коде виджета.
4. Метрики объявлены логическими пикселями при 100 % с указанием поведения при 125 / 150 %.
5. Перечень компонентов §2 закрыт полностью; для каждого заданы состояния и правило направления.
6. Раздел направления и bidi воспроизводит §3 без расхождений с ратификациями.
7. Блок токенов переносится копированием и не требует чтения картинки.

## С-1 · Два шрифтовых стека — свести, предварительно проверив

| Источник | Стек |
|---|---|
| Канон `design-system.md` §2 | `Segoe UI, Selawik, system-ui, sans-serif` |
| Канва §0 (новое) | `Segoe UI → Segoe UI Historic → Tahoma → Arial` |

Совпадает только первый член. Разбор:

- **`system-ui`, `sans-serif` — понятия CSS, в Qt их нет.** Канонический стек наполовину
  невыразим в целевой технологии — ровно тот класс, ради которого в канву и добавлялся §9.
- **`Selawik`** — открытый шрифт Microsoft, метрически совместимый с Segoe UI. В Windows
  **не установлен**: его ставят как замену там, где Segoe UI нет. В офлайн-сборке без
  установки его не будет — член стека мёртвый.
- **`Segoe UI Historic`** — шрифт **исторических письменностей** (клинопись, иероглифика и
  т.п.). Как запасной для иврита выбран, судя по всему, по созвучию имени. Иврит несёт сама
  Segoe UI; настоящие запасные с ивритом в Windows — **Tahoma** и **Arial**, и они в новом
  стеке уже есть.

Новый стек ближе к правде, но проверяется, а не утверждается. **Проверка на машине (Claude
Code, пять строк):** `QFontDatabase.families()` — что реально доступно; `writingSystems(family)`
— какие семейства объявляют поддержку `Hebrew`. Канон переписывается по результату.

## С-2 · `tnum` — назвать явно как невыразимое в QSS

Канон §2 требует табличные цифры и говорит «QFont.setStyleStrategy plus the `tnum` feature».
**В Qt Style Sheets свойства для OpenType-фич нет вообще.** `tnum` ставится только кодом —
`QFont.setFeature()` (Qt ≥ 6.7; у нас PySide6 6.11, значит доступно).

Это обязано стоять в §9 «невыразимое в QSS». Иначе исполнитель пропишет фичу в теме, молча
получит обычные цифры — и правое выравнивание величин, введённое ревью наряда 0007, перестанет
что-либо давать: разряды не встанут в столбик.

Отдельно проверить, что выбранное семейство **несёт** `tnum`: у Arial табличных цифр может не
быть, и тогда падение на фолбэк рушит колонку величин. Если фича недоступна — назвать
запасной механизм (моноширинное семейство только для числовых колонок).

## С-3 · Высота строки — сверить, не переписывать

Канон §3: `table row 40`. Канва прежней ревизии: 40 / 66 / 82 у отклонения и 28 / 43 / 58 у
находки — три уровня раскрытия. Вероятно совместимо (40 — свёрнутое состояние), но канон
про уровни молчит. Свести формулировки, чтобы сборка не выбирала между двумя числами.
