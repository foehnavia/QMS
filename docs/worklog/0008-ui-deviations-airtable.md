# 0008 — Deviations list: application theme + Airtable-shaped main screen

> **Наряд.** Ветка `run/qms-016`, цикл QMS-016 (чек-пойнт «прогон руками»).
> Пишет Cowork, исполняет Claude Code, отчёт — в конце этого файла (§ «Отчёт исполнителя»).
> Предшествующий наряд — `0007-ui-english-ltr.md` (English + LTR-шасси + направление
> на уровне абзаца). Этот наряд — следующий слой поверх него: **внешний вид**.

## Цель

Дать приложению собственную визуальную систему (белый + синий, светлая тема, не наследуемая
от Windows) и перестроить **основной экран — список отклонений** по образцу плотных
табличных инструментов: боковое меню с группами, вкладки-представления, панель фильтров,
таблица с состояниями строк и действиями на строке, информативный футер.

Экран выбран не случайно: он самый нагруженный и самый однотипный, поэтому решения, принятые
здесь, задают язык остальным экранам. Остальные разделы (`Items`, `Characteristic groups`,
`Reference data`) в этот наряд **не входят** — они переводятся на новую систему отдельным
нарядом, после того как язык проверен на живом прогоне.

## Что сделать

### §1 · Тема приложения (новый модуль `src/ui/theme.py`)

1. Модуль экспортирует палитру (§1 дизайн-системы) как именованные константы и функцию
   `apply_theme(app: QApplication) -> None`.
2. `apply_theme` ставит: `QPalette` со светлыми ролями, единый шрифт приложения
   (Segoe UI 9 pt / 13 px) **с включёнными табличными цифрами**, и глобальный `QSS`.
3. **Приложение перестаёт наследовать системную тему.** Проверяется тем, что скриншоты
   идентичны при Windows в светлом и тёмном режиме.
4. Вызов — в `src/app.py`, сразу после создания `QApplication`, до `setLayoutDirection`.
5. QSS не содержит ни одного литерального цвета: все значения — из констант модуля,
   собранные в строку. Цвет, найденный вписанным в QSS-строку руками, — дефект.

### §2 · Шасси окна (`src/ui/main_window.py`)

1. **Топбар 48**: марка приложения (значок 22 + «MIS-QMS»), разделитель, чип текущей базы
   (иконка + имя файла базы, не полный путь), справа — поле глобального поиска (280 × 28,
   пока **неактивно**, с подсказкой `Search deviations, items, WO…`; поиск — S8).
   Полный путь базы остаётся в футере (§8) — он нужен, но не в шапке.
2. **Сайдбар 240**, две группы с заголовками (10.5/700, letter-spacing 0.07em, `n-400`):
   - `WORK` — **Deviations** (значок треугольника-предупреждения, счётчик нерешённых
     синим бейджем), **Search** (неактивен, метка `S8`);
   - `CATALOG` — **Items** (счётчик), **Characteristic groups** (счётчик), **Reference data**.
   Группировка не косметическая: сверху то, чем пользуются ежедневно, снизу то, что
   настраивают. Активный пункт — фон `blue-100`, текст `blue-700`, вес 600.
3. Внизу сайдбара — строка «Offline · single workstation» (11.5, `n-400`), над ней разделитель.
4. **Свёрнутый сайдбар** (48, только значки) при ширине окна < 1180 — см. §10.
5. **Заголовок раздела 64**: название (18/650) + подзаголовок (11.5, `n-400`), справа —
   единственная первичная кнопка **`+ Add deviation`** (32, `blue-600`).

### §3 · Вкладки (44)

1. Шесть представлений: **Undecided · All · Approved · Rejected · Sorting · Repair**.
2. **Открывается `Undecided`** — это рабочая очередь: канон ставит решение шагом 8, и вопрос
   «что ещё не решено» — главный вопрос оператора к списку.
3. `Undecided` и `All` несут счётчик пилюлей; четыре исхода — цветную точку (§1) и число
   поменьше.
4. **Счётчики на вкладках не учитывают фильтры.** Они отвечают «сколько всего есть», и число,
   прыгающее от фильтра, оператор не просил. Счётчик, следующий за фильтрами, — в футере.
5. Активная вкладка: белый фон, рамка `n-200`, нижняя граница цвета фона (вкладка «срастается»
   с таблицей), вес 650.
6. Вкладка — **предикат по `decision_dev`**, не отдельный запрос: `Undecided` = `IS NULL`,
   исход = равенство, `All` = без условия.

### §4 · Тулбар (52)

Слева направо: **Filter** · **Sort** · **Fields** · растяжка · **Export**.

1. **Filter** — переключает панель §5. Когда фильтры применены: рамка и текст `blue-600`,
   фон `blue-50`, синий бейдж с их числом.
2. **Sort** — меню сортировок; по умолчанию `Date ↓` (как сейчас: `date desc, dev_number desc`).
   Текущая сортировка подписана на кнопке.
3. **Fields** — список колонок с галочками; подпись `8 of 10` — восемь колонок данных видимы, две скрыты. Скрытые по умолчанию —
   **Machine** и **NCR** (§6.6).
4. **Export** — выгрузка текущей выдачи в `.xlsx` (то, что видно: вкладка + фильтры +
   порядок сортировки + видимые колонки). Если это тянет на отдельный объём — **вынести
   заглушкой** (кнопка неактивна, подсказка «S7») и написать это в отчёте; лучше честная
   заглушка, чем половина выгрузки.
5. Активные фильтры показываются **чипами справа в этой же строке**: `Item · C1-08375A ×`,
   рядом `Clear all`. Чип с крестиком снимает свой фильтр.

### §5 · Панель фильтров (раскрывается под тулбаром)

Шесть полей в сетке 3 × 2, фон `n-50`, снизу рамка:

| Поле | Тип | Замечание |
|---|---|---|
| Item | выпадающий с поиском | по `item_number` |
| Work order | текст, подстрока | `פק"ע` — подсказка допустима рядом с английским именем |
| Date range | две даты | `numeric_field`, иначе даты развернутся |
| Machine | выпадающий | значения из существующих в базе |
| Zone | выпадающий | **через находки** — подпись «via findings» |
| Deviation type | выпадающий | **через находки** |

1. Фильтры **сужают внутри вкладки**, не отменяют её.
2. Zone и Deviation type ищут по находкам отклонения: отклонение попадает в выдачу, если
   **хотя бы одна** его находка отвечает условию. Это `EXISTS`-подзапрос, не `JOIN` —
   `JOIN` размножит отклонение по числу подходящих находок.
3. Панель закрыта по умолчанию; применённые фильтры видны чипами и при закрытой панели.
4. **Схема не меняется.** Фильтры — параметры запроса; состояние панели живёт в памяти окна.

### §7 · Домен (`src/domain/deviations.py`)

Схема **не меняется**. Меняются запросы:

1. `DeviationRow` получает `machine: str | None` и `ncr: str | None`.
2. `list_deviations` получает необязательные параметры фильтрации:
   `decision` (`None` = все, `"__undecided__"` = `IS NULL`, иначе значение),
   `item`, `wo_like`, `date_from`, `date_to`, `machine`, `zone_id`, `deviation_type_id`.
   Zone и тип — через `EXISTS` по находкам (§5.2).
3. Новая функция `decision_counts(session) -> dict[str | None, int]` — **один** запрос
   `GROUP BY decision_dev` для счётчиков вкладок. Не шесть запросов и не подсчёт в Python
   по полной выдаче.
4. Сортировка параметризуется, значение по умолчанию не меняется.
5. **Стоимость запроса ограничена и проверяется.** Число SQL-операторов при отрисовке списка
   не зависит от числа строк — тем же счётчиком `conftest.count_queries`, что в S5.

### §8 · Футер (36)

Слева направо: `Showing N of M` · разделитель · значок-контур + `undecided N` · разделитель ·
`1 row selected — DEV-…` (только когда есть выбор) · растяжка · `Database: <полный путь>`.

`Showing N of M` — **единственное место**, где число следует за фильтрами.

### §9 · Действия строки

1. Пять кнопок над таблицей **убираются**. Сегодня каждая сначала спрашивает «какая строка?»,
   и оператор выбирает строку, идёт к верху экрана и получает сообщение «ничего не выбрано».
2. Действия переезжают на строку: при наведении и у выбранной строки в последней колонке
   появляются две кнопки 24 × 24 — **карточка** и **`⋯`**. Меню `⋯`:
   **Open card** (Enter) · **Edit registration…** · **Set decision…** · разделитель ·
   **Delete deviation…** (красным).
3. **Двойной клик и Enter открывают карточку** — как сейчас; карточка остаётся рабочим
   экраном отклонения.
4. **Delete сохраняет подтверждение и его формулировку** — сколько находок и исследований
   уходит вместе с отклонением. Цена называется до удаления.
5. `Set decision…` остаётся доступным из списка — это решение S5, наряд его не пересматривает.

### §10 · Пустые состояния и клавиатура

1. Три пустых состояния (артборд `Screen states`): **фильтры ничего не нашли** (называет,
   сколько записей скрыто, и даёт «Clear all filters»), **пустая база** (объясняет, что
   отклонению нужны деталь и хотя бы одна находка, и отправляет в `Reference data` / `Items`),
   **пустая вкладка исхода** (короткая строка, без кнопки).
2. Клавиатура: `↑`/`↓` — строка, `Enter` — карточка, `Ctrl+N` — новое отклонение,
   `Ctrl+F` — фокус в поиск, `Esc` — снять фильтры.
3. Минимальное окно **1180 × 700**; ниже сайдбар сворачивается до значков (48), первыми
   скрываются `Findings` и `Inspections` — они счётчики, а подробность несёт карточка.

## Критерии приёмки

1. Приложение стартует со **своей** светлой палитрой; скриншоты в светлом и тёмном режиме
   Windows идентичны.
2. Ни одного литерального цвета вне `src/ui/theme.py` (проверяется тестом-гардом по `src/ui/**`,
   как гард на кириллицу из 0007).
3. Сайдбар: две группы, счётчики, активный пункт, свёрнутое состояние при узком окне.
4. Вкладки: открывается `Undecided`; переключение меняет выдачу; **счётчики не меняются от
   фильтров** (тест).
5. Фильтры: каждое из шести полей сужает выдачу; Zone и Deviation type не дублируют строки
   при двух подходящих находках (тест на отклонении с двумя находками одной зоны).
6. Чипы: каждый применённый фильтр виден чипом; крестик снимает свой фильтр; `Clear all`
   снимает все.
7. Таблица: ширины и высоты совпадают с §6.1 и `design-system.md` §3; три состояния строки
   различимы на снимке.
8. Направление: `Date` не разворачивается; ивритское значение в `Item` рисуется RTL;
   `Qty` выровнено вправо и сравнимо по разрядам. **Проверяется снимком, не свойством
   виджета** (репо-`CLAUDE.md` §9).
9. Действия: `⋯`-меню открывает четыре действия; двойной клик и `Enter` открывают карточку;
   подтверждение удаления называет число находок и исследований.
10. Футер: `Showing N of M` следует за фильтрами; `undecided` — нет.
11. Пустые состояния: все три отрисованы и объясняют причину.
12. Стоимость: число SQL-операторов не зависит от числа строк (счётчик запросов на 2 и 20
    отклонениях даёт одинаковое число).
13. **Схема не менялась** — ни таблиц, ни колонок, ни ревизий Alembic.
14. Все тесты зелёные; было **333**.
15. Снимки экрана на нативной платформе: список (вкладка `Undecided` и `All`), открытая
    панель фильтров, `⋯`-меню, три пустых состояния.
