# Наряд 0007 — интерфейс на английский, окно LTR

- **Задача / цель:** QMS-016 (чек-пойнт, ветка `run/qms-016`). Интерфейс приложения
  становится **англоязычным целиком**, шасси окна разворачивается **слева направо (LTR)**,
  а направление **данных** переносится с уровня окна на **уровень ячейки** — потому что
  бо́льшая часть содержимого таблицы отклонений ивритская и ячейки смешанные (иврит +
  английские термины + числа). Решение пользователя 2026-08-19, прогон шаг 2. До исполнения
  прогон **не продолжается**: дальше он идёт уже по английской сборке.

- **Вход:**
  - `docs/worklog/0006-run-qms-016.md` — журнал прогона (находки шага 2, инвентарь строк).
  - `docs/model/_overview.md` и файлы сущностей — **источник терминов** для подписей.
  - `docs/specs/deviation-entry.md`, `deviation-card.md`, `cg-editor-and-mapping.md` —
    as-built спеки; они цитируют нынешние **русские** подписи и правятся этим же нарядом.
  - `docs/architecture.md` §3 · корневой `CLAUDE.md` §9 (конвенции UI/тестов).

## Почему наряд вообще есть

Язык интерфейса **никогда не был решён**. `architecture.md` §3 выбирает PySide6 ради
нативного RTL/bidi, но обосновывает это ивритом **в данных и в Excel-источнике импорта**;
про язык подписей в каноне нет ни строки, в `decisions.md` — тоже. Русские подписи затекли
из нарядов S2–S5, спеки зафиксировали их как as-built, ревью язык не проверяло. Это дыра в
каноне (корзина **М**), а не косметика.

**Направление окна — следствие, но не упрощение.** Сейчас `app.setLayoutDirection(RightToLeft)`
— обосновано тем, что «иврит основной язык данных». Разделяем два разных вопроса, которые
одна глобальная настройка склеила:

- **язык и раскладка шасси** (навигация, кнопки, заголовки, рамки диалогов) — English + LTR;
- **направление данных** — определяется **содержимым каждой ячейки**, а не окном.

> [!warning] Уточнение пользователя (2026-08-19, прогон шаг 2). Первая редакция этого наряда
> исходила из того, что иврит живёт в двух-трёх полях свободного текста, и обещала снять
> bidi-хелперы «за ненадобностью». **Это неверно.** Бо́льшая часть содержимого таблицы
> отклонений — иврит, ячейки смешанные: иврит (основной текст) + английские технические
> термины + числа (допуски, величины, направление). Хелперы **не снимаются** — они
> перестают быть точечными заплатками под RTL-окно и становятся механизмом уровня ячейки.

LTR-шасси всё равно оправдано: класс дефектов S2–S5 (даты задом наперёд, разворот `±`,
отрывающаяся пунктуация в русских/английских подписях) порождён именно тем, что **интерфейсные**
строки жили в RTL-контексте. Данные же остаются двунаправленными, и с ними работа не
уменьшается, а становится системной.

## Что сделать

1. **Все пользовательские строки в `src/` — на English.** Инвентарь на момент наряда:
   **425 строковых литералов с кириллицей в 28 файлах** (docstring исключены). Кириллица в
   семантической позиции — сравнение, ключ словаря — **не найдена** (проверено AST), значит
   перевод не меняет логику: строки только отображаются.

   Крупнейшие: `ui/deviation_dialog.py` 61 · `ui/card_dialog.py` 43 · `ui/cg_editor.py` 34 ·
   `ui/finding_dialog.py` 25 · `ui/cg_dialog.py` 23 · `ui/mapping_dialog.py` 22 ·
   `domain/groups.py` 21 · `ui/deviation_view.py` 21 · `ui/reference_view.py` 17 ·
   `domain/deviations.py` 16 · `ui/item_dialog.py` 15 · далее по убыванию.

2. **Термины подписей берутся из канона, а не изобретаются.** Экран обязан говорить теми же
   словами, что `docs/model/` — иначе спека и интерфейс снова разойдутся:

   | Канон | Подпись UI |
   |---|---|
   | Item | Item / Items |
   | Characteristic (item, local #) | Characteristic · Local number |
   | CharacteristicGroup | Characteristic group (CG) |
   | g-position | g-position (`g1…gN`) |
   | Mapping | Mapping · Bind to canon… |
   | Deviation | Deviation / Deviations |
   | Finding | Finding / Findings |
   | Inspection | Inspection |
   | decisionDev (4 исхода) | Decision — approved / rejected / sorting / repair |
   | explanation | Explanation |
   | Zone · Deviation type · Inspection type | Zone · Deviation type · Inspection type |
   | WO (`מנה`/`פק"ע`) | Work order (WO) |
   | NCR · quantity · nominal · tolerance | NCR · Quantity · Nominal · Tolerance |
   | L1 / L2 | Exact precedents (L1) · Descriptive precedents (L2) |

3. **Доменные сообщения об ошибках — тоже English** (`domain/errors.py` и тексты в
   `domain/*.py`). Формально это не UI-слой, но пользователь читает их в модальном окне —
   значит это интерфейс. Слоение домен/UI при этом не нарушается: меняется только текст.

4. **Направление — три уровня, а не одна глобальная настройка.**

   | Уровень | Что | Направление |
   |---|---|---|
   | Шасси | навигация, кнопки, заголовки окон, рамки диалогов, статус-бар | жёстко **LTR** |
   | Ячейка / поле данных | значение в таблице, редактор поля | **по содержимому** |
   | Вкрапление | English-термин или число внутри ивритской фразы и наоборот | изолят |

   - `app.setLayoutDirection(Qt.LayoutDirection.LeftToRight)` — это **только шасси**.
   - **Уровня «ячейка» в коде сейчас нет вообще** — направление одно на всё приложение.
     Это главная работа наряда, не перевод строк.
   - `ui.common.iso` (**FSI** `U+2068` … `U+2069`) **не меняется**: first-strong-isolate уже
     определяет направление по первому сильному символу внутри и потому работает в обе
     стороны. Менять надо не хелпер, а широту и последовательность его применения.
   - `ui.common.ltr_field` **не удаляется**. Он нужен там, где текст рисует сам Qt
     (`QDateEdit`, `QSpinBox`) и обернуть строку нечем. Переименовать честно — `numeric_field`
     — и применять по признаку «содержимое гарантированно латинско-цифровое» (дата,
     количество, допуск, величина), а не по признаку «окно RTL».
   - `ui.common.apply_rtl` из «подстраховки под RTL-приложение» становится точечным
     инструментом для ивритских полей — оставить, переописать docstring.
   - `ui.common.russian_buttons` **удалить**: он существует, чтобы перебивать английские
     подписи Qt на русские. Save / Cancel / OK приходят от Qt по умолчанию.

4а. **Направленно-осознанная ячейка — новый механизм (ядро наряда).**

   - Ввести делегат отрисовки таблиц (item delegate), который для каждой ячейки вычисляет
     базовое направление и выравнивание **по значению**: первый сильный символ иврит → RTL +
     выравнивание вправо; латиница/цифра → LTR + влево. Числовые колонки (величина, допуск,
     количество, дата) — всегда LTR независимо от содержимого.
   - Редакторы свободного текста (`Finding.comment`, обоснование решения, текст протокола
     исследования) — направление по содержимому, **не форсировать** ни LTR, ни RTL глобально.
   - Смешанные ячейки «иврит + English-термин + число» обязаны читаться верно: порядок слов,
     положение хвостовой пунктуации и скобок, знак `±`/`−` при своём числе.

   > [!question] **Точное правило для смешанной ячейки наряд НЕ фиксирует — оно снимается с
   > реальных строк в прогоне.** Ратификация S5 («изолят один — вокруг собранной строки»)
   > выведена на однородной строке вида `− 0.05` и для смешанной ивритско-английской ячейки
   > не проверялась: обёртка целиком берёт направление по первому символу и может развернуть
   > остальное. Задача исполнителя — поставить **механизм и стенд**, а не угадать правило:
   > собрать тестовый набор из реальных смешанных строк (иврит + термин + число + пунктуация)
   > и вывести в снимки экрана. Правило ратифицируется после прогона и уходит в `CLAUDE.md` §9
   > и в UI-guidelines.

5. **Сид справочников** (`seed/reference.py`) — проверить, что ни одного не-английского
   значения. Значения справочников по решению пользователя тоже только English.

6. **Тесты.** Обновить только те, что сверяют **текст интерфейса** — ориентировочно
   `test_ui_card.py` (27 мест), `test_ui_deviation.py` (19), `test_ui_smoke.py` (9),
   `test_ui_canvas.py` (7). Русские **сообщения assert** и тестовые **данные** (`'CG-новая'`,
   `'100 % контроль по диаметру'`, `'влияния нет'`) — не интерфейс, их не трогать; они
   изображают то, что оператор реально вводит.

7. **Новый гард-тест — «в `src/` нет кириллических строковых литералов».** Разбором AST, как
   уже сделанный гейт `make_finding`: обходим `src/**/*.py`, для каждого `ast.Constant`-строки
   вне docstring проверяем отсутствие кириллицы. Комментарии и docstring **исключены
   намеренно** — они внутренние, не интерфейс, и остаются русскими. Без этого гарда язык
   уедет обратно на первом же спринте, ровно как уехал в первый раз.

8. **Спеки as-built** — заменить процитированные русские подписи на новые английские:
   `deviation-entry.md` §1 (`«Отклонения»`, `«Добавить отклонение…»`, `«Открыть…»`,
   `«Карточка…»`, `«Решение…»`, `«Исследование…»`, `«Привязать к канону…»`),
   `deviation-card.md`, `cg-editor-and-mapping.md`. Поле `amended_by: QMS-016`.

9. **Канон ветки:**
   - `docs/architecture.md` §3 — записать направление окна LTR и обоснование (иврит точечно);
   - `docs/decisions.md` — ратификация: **язык интерфейса — English, окно LTR**, с основанием
     («язык не был решён, затёк из нарядов; RTL-окно ради двух-трёх полей породило класс
     дефектов S2–S5»);
   - корневой `CLAUDE.md` §9 — переписать блок «Bidi» под LTR-окно: что теперь изолируется,
     что `ltr_field` снят, что правило «один изолят вокруг собранной строки» сохраняется.

## Критерии приёмки

1. Гард-тест (п. 7) зелёный; в `src/` не осталось ни одного кириллического строкового литерала.
2. Весь набор тестов зелёный (было 303 до наряда; ожидается 304+ с гардом).
3. Приложение стартует, окно **LTR**, статус-бар несёт строку базы; во всех четырёх разделах
   и во всех диалогах подписи только английские — проверяется прогоном на нативной платформе
   со снимками экранов (offscreen для снимков непригоден, `CLAUDE.md` §9).
4. Дата в редакторе читается `19.08.2026`, а не `2026.08.19`; допуск `± 0.05` не разворачивается.
5. **Ивритская ячейка в LTR-таблице** выровнена вправо и имеет RTL-базу; латинская —
   влево и LTR; числовая — всегда LTR. Проверяется тестом на делегат (направление и
   выравнивание для трёх видов значения) **и** снимками экрана.
6. **Стенд смешанных строк** собран: тестовый набор из реальных ивритско-английско-числовых
   значений выведен в снимки, по каждому видно, что порядок и пунктуация не поехали.
   Правило для смешанной ячейки — в отчёт исполнителя как наблюдение, **не как ратификация**.
7. Спеки `docs/specs/*` не содержат русских подписей интерфейса.
8. `decisions.md` несёт ратификацию языка и направления; `CLAUDE.md` §9 описывает LTR-правило.

## Чего не трогать

- **Ветка.** Вся работа — в `run/qms-016`. В `main` не коммитить ничего.
- **`docs/model/`** — модель этим нарядом не меняется. Пересмотр CG (CG как отдельная
  сущность) — отдельный наряд, после того как прогон упрётся в старый формат.
- **Зеркало концепта в волте** — заморожено на S5, из ветки не регенерируется.
- **`app.sqlite`** — база прогона отдельная (`data/qms016.sqlite`), синтетику S2 не трогать.
- **Схема БД** — миграции этим нарядом не пишутся: меняется только текст и раскладка.
- **Комментарии и docstring** в коде — остаются русскими, это внутренний слой.

### Наблюдение по смешанной ячейке — **не ратификация**, снято со стенда

Правило S5 («изолят один — вокруг собранной строки») выведено на однородной строке и на
смешанной ячейке **не работает**. Стенд показывает три случая рядом:

| Ячейка (логический порядок) | `iso` вокруг всей строки | `joined` (изолят на токен) |
|---|---|---|
| `אזור הברגה · thread burr · − 0.05` | `אזור הברגה · − 0.05 · thread burr` — токены переставлены | верно |
| `סטייה בקוטר · C1-08375A · WO W26007336` | два латинских токена поменялись местами | верно |
| `קוטר פנימי · ⌀ 3.75 · +0.02 / −0.05` | допуск показан как `0.05− / 0.02+` | верно, знаки на месте |

Причина: изолят вокруг всей строки задаёт **только базу** — а базу и так задаёт делегат.
Порядок самих токенов он не держит: внутри изолята они остаются отдельными runs.

Предлагаемая формулировка (одна вместо двух, объединяет S5 и это): **ровно один изолят на
атомарный токен** — ни двух вокруг частей одного токена (дефект S5: `− 0.05` → `0.05 −`), ни
одного вокруг нескольких (дефект, найденный здесь). Атомарный токен — тот, внутри которого нет
сильных символов **или** который читается как одно целое (бизнес-номер, дата, знак с
величиной). Механизм: `ui.common.iso` для атомарного, `ui.common.joined` для составного.
Записано в `decisions.md` и `CLAUDE.md` §9 **как правило исполнителя**; ратификацию на уровне
канона оставляю за Cowork.

### Отклонения от наряда / вопросы Cowork

1. **Дефект самого механизма, найденный снимком, а не тестом.** Первая редакция делегата
   ставила ивритской ячейке `AlignRight`. На экране строка при этом липла к **левому** краю:
   Qt накладывает `QStyle.visualAlignment(direction, …)` поверх `displayAlignment`, и под RTL
   она меняет левое на правое — то есть просьба «вправо» превращается в «влево». Тест этого не
   видел, потому что сверял **запрошенное** выравнивание. Исправлено: делегат задаёт
   выравнивание **логически** (`AlignLeft` = «к началу строки»), сторону выбирает Qt; тест
   сверяет отрисованное через `visualAlignment`. Отдельный довод в пользу того, что прогон со
   снимками — часть приёмки, а не украшение. Ратифицировано в `decisions.md`.

2. **Сверх наряда — три вещи, все мелкие.** (а) Подпись баллона `№N` → `#N`: `№` (U+2116) — не
   кириллица, гард его не ловит, но это русская типографская конвенция. (б) Составная строка
   справочника (`имя · default · references: N`) переведена на `joined` — при ивритском имени
   пометки уезжали вперёд. (в) `docs/_INDEX.md` дополнен разделом про инструменты прогона: без
   этого снимки, которых требует критерий 3, негде найти. Если последнее лишнее — уберу.

3. **Выравнивание числовых колонок — влево, не вправо.** Наряд задаёт для них только
   направление (LTR), про сторону не говорит. Выбрано «влево», как у латинского текста: держит
   ровный левый край таблицы. Если по типографике нужнее правый край для величин — правка на
   одну строку в `DirectionalDelegate`.

4. **Находка В-4 закрыта наполовину осознанно.** Подсказка переехала к списку, кнопки ушли
   вниз — воздух распределён. Но список по-прежнему растянут на всю высоту: справочники в
   производстве длинные (по решению пользователя — «полный производственный набор»), и
   фиксировать высоту по трём стартовым значениям было бы неверно. Если на реальном наборе это
   всё равно читается плохо — отдельная правка.

5. **Иврит в интерфейсных строках оставлен точечно и намеренно** — там, где это **термин
   документа**, а не подпись: `פק"ע` в подсказке поля WO, `מק"ט` в подсказке номера детали,
   `אישור חריגה` в тексте про обоснование, `מדיד` в примере комментария. Гард их пропускает (он
   ловит кириллицу), а оператор читает их как имена бланков, а не как перевод.

6. **Что осталось нетронутым, как велено:** `docs/model/`, зеркало концепта, схема БД
   (миграций нет), `app.sqlite` и `data/qms016.sqlite`. Демо-база снимков —
   `build/screens-demo.sqlite`, пересоздаётся при каждом запуске.

7. **Прогон можно возобновлять с шага 3** — уже на английской сборке. Наполнение справочников
   производственным набором в этот наряд не входило.
