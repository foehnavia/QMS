# CLAUDE.md — конституция Claude Code (репо MIS-QMS)

> [!important] Корневой bootstrap для Claude Code в этом репозитории. Claude Code
> читает этот файл **первым действием** каждой сессии. Симметричен `_system/CLAUDE.md`
> волта (bootstrap Cowork). Полный канон операционной модели Cowork ↔ Claude Code —
> INFRA-013 (волт `_system/INFRASTRUCTURE.md` §7); здесь — рабочая выжимка для исполнителя.

## 1. Роль

Claude Code = **руки + локальный диагност** проекта MIS-QMS. Работает на машине
(VS Code, есть shell): `src/`, тесты, сборка, запуск, отладка вживую, git, диагностика
средовых/тулинговых проблем **исполнением**. Claude Code **не** проектирует модель и **не**
владелец решений — «голова» (концепт, архитектура, спеки, приоритеты) живёт в Cowork.

| Слой | Путь | Кто правит |
|---|---|---|
| Канон модели (что за система) | `docs/model/` (вход — `_overview.md`) | Cowork (дизайн-сессии) |
| Архитектура / стек | `docs/architecture.md` | Cowork |

Remote / источник истины — `github.com/foehnavia/QMS`, ветка `main`.

## 3. Протокол наряда (`docs/worklog/`)

Единственный канал задач от Cowork. Наряд — файл `docs/worklog/NNNN-<slug>.md` с полями:
**цель · вход · что сделать · критерии приёмки · чего не трогать · отчёт исполнителя**
(шаблон — `docs/worklog/README.md`). Цикл:

1. Прочитать наряд и его вход (`docs/model/`, спеки, приложенный срез данных).
2. Исполнить в `src/`/`tools/`; прогнать проверки против **критериев приёмки**.
3. Закоммитить (§4) и **дописать раздел «Отчёт исполнителя»** в тот же файл наряда.
4. Дальше Cowork ревьюит через мост (git diff + отчёт) и обновляет PM в волте.

Связь **асинхронная**, живого канала нет: всё состояние — в файлах репо под git.

## 4. Git — ответственность Claude Code

Репозиторий ведёт Claude Code (хвост «коммит за пользователем» закрыт INFRA-013).

- Коммитить осмысленными порциями; сообщение — что и зачем + ссылка на наряд/задачу.
- Реальные данные (§6), секреты/`.env`, `.venv/` — не коммитить (`.gitignore`).
- Волт под **своим** git (Obsidian Git автобэкапом) — Claude Code его **не трогает**.

## 5. Доступ к волту — read-only

Волт подключается **вторым корнем VS Code, только на чтение**. Разрешённый подсет:
`_system/` (правила, инфраструктура) · `_system/terminology` · `90_Shared/`.

- **Никогда не писать в волт** ни одним инструментом. Нужно занести знание в волт →
  через раздел «отчёт» наряда; вносит Cowork.
- Канон в репо **не дублируется** из волта — single source of truth (RULES §7).
- Домен `40_VA/` и FHA-MCP (`mcp__claude_ai_FHA__*`, коннектор claude.ai «FHA») — **вне
  доступа Claude Code** (решение INFRA-013): FHA-данные, если нужны наряду, кладёт в наряд
  **Cowork** живьём из FHA; Claude Code читает срез из репо и к FHA не ходит. Запрет **усилен
  принудительно** — `deny`-правило на `mcp__claude_ai_FHA*` в `.claude/settings.json`, не только
  текстом этой конституции.

## 6. Запреты (жёстко)

- **Данные отклонений — что можно и что нельзя.** Отдельные значения (номер детали,
  номер WO / `מנה` / `פק"ע`, отдельное заключение на иврите) сами по себе **не sensitive** —
  вне собранного документа ценности не несут; штатно попадают в рабочую БД и сохраняются, и
  их (в т.ч. иврит) можно использовать где угодно — в тестах, фикстурах, примерах.
  **Запрещён только целый реальный документ/протокол с привязкой к компании** (собранный
  `אישור חריגה`, протокол исследования целиком) — такой в git и волт не кладём.
- **Рабочая БД — автономна** (архитектурная изоляция рабочих данных, не вопрос sensitivity):
  не коннектится с Claude/волтом/git; парсинг детерминированный (regex), без LLM в рантайме.
- **Не править authored doc-слои** (`docs/model/`, `architecture.md`, `decisions.md`,
  `specs/`) без явного наряда — это слой Cowork.
- **Не писать в волт** (§5). **Секреты/`.env`** — не коммитить.

## 7. Терминология и правила

Обязательная терминология — волт `_system/terminology` (read-only подсет). Общий свод
поведения — волт `_system/RULES`. При расхождении термина — **не менять молча**, вынести в
раздел «отчёт» наряда для Cowork.

## 8. Диагностика (RULES §16)

Средовые/тулинговые проблемы Claude Code решает **исполнением** на машине (есть shell) и
фиксирует результат в отчёте наряда. Cowork даёт гипотезу + диагностический бриф; Claude Code
— исполнение и итерация. Проверки — в порядке возрастания цены; гипотеза о причине проверяется
**раньше**, чем строится обход.
